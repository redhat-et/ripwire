### Changed — a short `--for` row keeps its end line: `e=` rides beside `l=` on the sigs rows past rank 10

On page 1 of the default `--for` answer, a `<sigs>` row with `r` above 10 is served in its short form. That form kept `l= n= p= r=` and sent `e=` to the `<sigx>` block on a later page, so the row named where a definition starts and not where it ends. It now keeps `l= e= n= p= r=`: in the line form the row reads `P:L-E N`, in the element form (`RIPWIRE_NO_ROWLINES=1`) `<d l= e= n= p= r=/>`. A reader can range-read the definition from page 1 without a second call. Nothing else about the row changes, the line grammar and `test/rowlines.py` already spelled `-E` and needed no change, and a row whose extent is not known (a markdown heading, a config key, an `extent_suspect` row) still carries no `e=`, never a 0. The whole answer's bytes do not move: the attribute changes element, not count, and `<x>` no longer repeats it.

Measured on 89 dev questions against the parent binary, page 1, both answers decoded with `test/rowlines.py`: of the 123 gold functions page 1 names, those with a usable `l=`..`e=` range go from 80 to 96 (0 lost), and the cells where every gold function has a range from 45 to 51. The four orientation rungs are unchanged (FILE 84, FUNC 62 / 65, BODY 24; 0 cells up, 0 down, no cell with fewer hits). The cost is page-1 room: the `e=` bytes are paid on page 1 (1,355 more rows carry one), and the page cut answers by moving 117 unranked `<tail>` pointer rows, at most 3 per answer in 73 of the 89, to page 2. What it does NOT mean: the range is the parser's body-inclusive span, so a decorator or return type can sit above `l=`; `<b>`, `<h>`, `<c>`, `<skip>` and `<ls>` rows still print `l=` without `e=` (they are not sigs rows; two `<b>`, one `<h>` and one `<ls>` gold function stay start-only on this set); and whether an agent then reads fewer lines is untested. Not applied where the short form is not: `--legend=first`, a token budget, `--signatures-only` (whose rows already carry `e=`), MCP, non-XML output. `test/forendlinecheck.sh` pins it in both forms against the `RIPWIRE_NO_SIGX=1` twin, with known first and last lines on a fixture and two mutation negative controls; `test/forsigxcheck.sh` (S2, S8) reads the short form as `l e n p r`.
