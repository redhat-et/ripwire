### Fixed — an ObjC++ `std::X()` call no longer binds an unrelated in-repo `X`

In a `.cpp`, `.cu` or `.metal` file, a call written `std::X( … )` binds only a definition inside namespace std, and is refused (counted in the header's `external=`) when the repository has none. An Objective-C++ (`.mm`) file did not get that rule. tree-sitter-objc has no `::` token, so it parses `std::unreachable()` as an error-recovery node spelling `std::` next to a bare `unreachable()` call. The reference therefore arrived with no qualifier, and a lone method such as `Cursor::unreachable` took the call at full confidence. `std::move` and the other names in the Phase-5 table were already refused; `std::unreachable` and every other name outside that table were not.

Ingest now reads the qualifier back from the bytes written before the call name: `std::`, `::std::`, `std::__1::`, `std::ranges::`, with blanks allowed around `::`. It keeps that qualifier only when the chain's root is `std` and the nearest `::` lies inside an error-recovery node, so a `::` that ends a comment above a bare call is never taken as a qualifier. The existing std guard then decides the call exactly as it does for C++. A def inside namespace std still binds; a same-named class member does not.

What does not change: a non-std ObjC++ chain (`vendor::halt()`) still reaches the resolver unqualified, as before, and keeps its current edges. A template-id segment (`std::vector<int>::size()`) stops the read-back and is not recovered. `test/stdqualcheck.sh` §7 (formerly a pinned floor) and the new §16 gate this, including ObjC++, Metal and CUDA controls. The extraction change moves `kParserVer` (see the versions fragment at release).
