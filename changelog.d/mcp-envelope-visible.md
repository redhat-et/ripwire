### Fixed — MCP truncation and assumption disclosures reach the model, not only the JSON-RPC client

An MCP result carried its disclosures beside `content`: `_assumed_root` (no `path` was given), `_memory_stop` (the memory guard cut the index), `_history_cut` (a git history walk was cut) and `_fresh:"reindexed"` with its two counts. A host hands the model `content` only. In 102 sampled Claude Code results, none carried `_index` or `_fresh`, so for the agent "every truncation is disclosed" did not hold. A result that carries any of these now says the same sentence inside the answer, in the answer's own form, and only when there is a note. An XML answer gains a final `<notes><n k="KEY">sentence</n></notes>` child, before a trailing ref-posture `<about>`, so it is still one well-formed document. A JSON answer gains a `"_notes"` member, so it still parses. The plain-text `memory_recall` answer gains trailing `KEY: sentence` lines. An answer with nothing to disclose is byte-identical to before. A first version used a second content block. CI on #774 showed it breaking every gate that joins the blocks into one document, and that is how hosts treat them too. The machine copies stay where they were. `_fresh` stays machine-only on purpose: it is about the call (whether the server rebuilt an index it already held), it limits nothing, and a reindexed answer must equal a cold server's, byte for byte (`mcpincrementalcheck`, `freshnesscheck`). `_memory_peak` stays machine-only on purpose too: the answer it rides is whole, its number differs run to run, and the CLI says it on stderr, never in a verb's answer.

`test/mcpenvelopevisiblecheck.sh` forces each key. On the parent, 4 of its 13 arms fail; on this change all 13 pass.
