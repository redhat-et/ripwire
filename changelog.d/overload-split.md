### Fixed — a C++ call whose argument types pick one overload, and a Go call through a generic field, no longer split

A C++ call to one class's same-arity overloads was split onto every overload (`prov="split"`), even when the arguments' declared types pick one of them. Now, when every argument is one of the calling function's own parameters and exactly one non-template overload takes each argument as its exact declared type, that overload is the edge, bound alone. Otherwise the split stays: no overload takes every argument by identity (one reachable only by a conversion), or a guard stops the pick: a template overload, a const or pointer mismatch, a shadowed parameter, a different namespace, a receiver no lookup proved, or a qualifier naming another class. On envoy, `WatermarkBuffer::prepend( absl::string_view data )` now calls only `OwnedImpl::prepend( absl::string_view )`. 41 envoy call sites move from split to one edge.

A Go call through a struct field whose type is a qualified generic instantiation (`suppressedModules addrs.Set[addrs.Module]`) now reaches that package's type (`addrs.Set.Add`), not every type named `Set`. Other qualified field types also bind to their own package's type when it defines the method. Interfaces and embedded types keep their previous answer. New gate arms in `test/aritycheck.sh` (section 3d) and `test/receiverevidencecheck.sh` (G).
