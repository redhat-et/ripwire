### Fixed — a cold map of a large tree asks the receiver's method lookup once per question, not once per call

The receiver-evidence method lookup (`x = Impl(); x.m()`: Impl's own `m`, else the shallowest base level that defines it) walked the receiver type's base levels again on every call, de-duplicating each push by a scan of everything already reached and looking every class of every level up by name. Where a class name repeats across a tree — chaUp merges every base of every class of that name — that walk was about a tenth of llvm-project's cold resolve loop. The answer depends only on the type, the method name, whether the call is a `super` call, and the one class definition the type resolved to, so it is now kept per such question and every later call reads it back. Every answer is unchanged byte for byte. `RIPWIRE_STATS` prints the counts as `[mem] recv_method`, and `test/guardedwalkcheck.sh` holds the lookup to one walk per question however many calls ask it.
