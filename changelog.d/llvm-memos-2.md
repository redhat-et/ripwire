### Fixed — a cold map of a large tree answers three per-call lookups once per question, or without building a key

The receiver-evidence method lookup (`x = Impl(); x.m()`: Impl's own `m`, else the shallowest base level that defines it) walked the receiver type's base levels again on every call, de-duplicating each push by a scan of everything already reached and looking every class of every level up by name. Where a class name repeats across a tree — chaUp merges every base of every class of that name — that walk was about 7% of llvm-project's cold resolve loop. The answer depends only on the type, the method name, whether the call is a `super` call, and the one class definition the type resolved to, so it is now kept per such question and every later call reads it back. A call to a name that function-local definitions share (`helper` nested in many functions) set aside every such definition the call cannot reach, then filtered the name's whole list of definitions — on every call, though a call that no local definition's function holds always gets the same answer: the list without its local definitions. That list is now kept per name, and whether a local definition holds the call is one search of the name's local definitions by file and position; on llvm-project 765,281 of 771,457 such calls are answered from the kept list. Class identity's walk over the real subclasses of a receiver class (a virtual call on a type that declares the method but defines it nowhere) asked the definitions table for "Class::method" at every subclass it visited, for every (class, method) — building the key text and hashing it into the whole table each time; the table's keys are now split once into (scope, name) numbers, each class keeps its scope's number, and a visit is one integer-keyed probe (a method name containing a `:` keeps the text lookup). Every answer is unchanged byte for byte. `RIPWIRE_STATS` prints the counts as `[mem] recv_method`, `[mem] reach_by_name` and `[mem] canon_split`, and `test/guardedwalkcheck.sh` holds the method lookup to one walk per question however many calls ask it checks that every call no local definition holds is answered from the kept list, and that every subclass visit is answered by the split keys.
