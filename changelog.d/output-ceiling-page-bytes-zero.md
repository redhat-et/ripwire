### Added — `--for --page-bytes=0` says so on stderr when the whole answer is over the output ceiling

`--page-bytes=0` asks for the whole `--for` answer in one call, and it still prints it whole and byte for byte. On GA1 DEV 5 of 11 such answers were over 24,000 characters and 2 over 30,000 (largest 43,403) — past Claude Code's inline limit, where the agent sees a file path and a 2,000-character preview. When the answer is over the 24,000-character output ceiling (`src/outputceiling.h`), one line now goes to stderr **before** the answer — so it lands inside that preview — naming the answer's size and that dropping `--page-bytes=0` serves it in pages. Under the ceiling nothing is printed. Gate: `test/outputceilingcheck.sh` (W1/W2, and stdout byte-identical to before).
