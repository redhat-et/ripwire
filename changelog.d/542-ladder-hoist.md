### Changed — warm `--deps` and `--for` on large trees use 1.5-3x less CPU (#542)

The by-name call resolver asked, for every candidate definition of a called name, facts that depend only on the call: the receiver's root name, whether it is `this`/`super`, the caller's class, and for JS/TS the `require()` alias and the path it joins to. They are now read once per call and tested per candidate, and the "is this owner a class" table is one byte per symbol instead of a lookup. Warm runs (cache hit) measured with user CPU (instructions retired in brackets): vscode `--deps` -67 % (-70 %), cockroach `--for` -57 % (-60 %), envoy `--deps` -35 % (-36 %). Cold runs (no cache) gain less: instructions -14 % on vscode, -12 % on cockroach and -4 % on envoy. Peak footprint is unchanged in each of those runs. The new storage is one byte per symbol plus one small per-call struct. The measurement is one machine and three repos; wall time was noisy on a shared machine, so the figures above are CPU and instruction counts, not wall time.

Answers are unchanged where it was checked: 321 in-sample `--for` calls and 12 base-versus-new output pairs on those three repos (9 warm, 3 cold) are byte-identical, as are 92 caller and callee outputs on a crafted Python, JS, TS, Go and Java tree. A module alias is proved by its own call's `require()` path, never by a neighbouring call's (a new case in `test/tsimportprecisecheck.sh`).
