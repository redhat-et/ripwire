### Changed — unused-in-file fix round 1: `unused` is printed only when the scan can prove it

The `--for` "unused in file" table reads every text file under the root, indexed or not (`.vue`, `.svelte`, `.ipp`, Procfile, templates, `vendor/`, `dist/`), and reads `unknown why=unseen` when a file cannot be read. `#` opens a comment only where the language facts say so (Python, shell, Ruby), never in Rust attributes, C/C++ directives or JS/TS private fields. One-character names are scanned. A distribution's public API (a Python package with a build table, a published package.json, `export type *`) reads `why=api`, and the legend no longer says `never live`. File-path routes, `__init_subclass__` and metaclass registries, joined string names, dynamic directory imports and a stem aimed at the target module read `unknown`; the short-stem length rule is gone.

Fix round 2 keeps to the same rule, `unused` is printed only on a proven shape. A C or C++ call no longer reads as a prototype. Non-ASCII names are one name. `.mdx` and `.txt` are read; prose docs are the one kind that is not, and the legend says so. A directory that cannot be entered counts as unseen, and `unseen_by=` names the limit that fired. Binaries count toward no cap. `* ` and `// ` line heads are comments only where the language has them. A module object indexed or passed along, a default export with an importer, a stem joined to anything computed, a multi-line decorator or attribute, a runtime-called name, and a module nothing imports (`why=unimported`, Python, TS, JS) all read `unknown`.
