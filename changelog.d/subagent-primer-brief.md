### Added — the subagent primer delivers `--brief` for the spawn's task, and `--handoff=TASK`

The opt-in subagent primer (`skills/install.sh --hook-subagent-primer`) now gives a fresh subagent the `ripwire <root> --brief="<its task>"` page (3.5/5/7 KB by size class) instead of the two-step "orient, then check" text, when the hook can tell which task the subagent was given. A SubagentStart payload carries no prompt, so the installer also registers the primer as a PreToolUse hook on `Agent|Task`. That half stores the spawn's prompt for up to 120 s (user-only file under `$TMPDIR`) and prints nothing. The SubagentStart half uses it only when exactly one stored prompt of this session matches the subagent's type, the prompt is at most 4096 B and not already a `<brief>` page, and ripwire answers with one `<brief>` document within `RIPWIRE_SUBAGENT_BRIEF_MS` (default 8000). In every other case (a resume, a parallel fan-out of one type, a timeout, any other output) the subagent gets the two-step text, byte for byte as before. `RIPWIRE_SUBAGENT_BRIEF=0` (or `subagent_brief=off` in `~/.ripwire/meter.conf`) turns the brief off. The primer's SubagentStart entry is registered with a 15 s timeout. Each row in `~/.ripwire/subagent_primer.jsonl` gains `brief` and `brief_reason` (row `v` 2); the prompt is never logged.

`ripwire <dir> --handoff=TASK` prints the `--handoff` continuation packet, then the `--brief=TASK` page, so the next session gets its task's entries, build and test commands quoted from manifests, act ranges, where-else and conventions with the packet. The packet is read on the index the task's `--brief` builds, which also records value uses, so a heuristic row's doc score, its `candidates=` count and the header's `est_tokens=` can differ slightly from a bare `--handoff`. `--brief-bytes=N` sizes the brief part. It is refused beside `--for`, `--pack-task` or `--brief`. `RIPWIRE_HANDOFF_TASK=0` makes it a bare `--handoff`. New gate: `test/handofftaskcheck.sh`; `test/subagentprimercheck.sh` gains arms (P)-(T).
