### Fixed — the warm snapshot is keyed on `--ignore-tests` and on the build that wrote it

Two inputs could reach a stored graph without being in the snapshot's key. Neither was seen to change an answer; both are closed because a stale snapshot is a wrong answer at exit 0. (1) `--ignore-tests` drops the test files' symbols, references and bindings between the stored model and the graph, and the graph section's guard is three counts. A test file that adds bindings only (`let x: Foo;`, `export default helper;`, `using namespace std;`, `extern int counter;`) left the three counts equal, so a graph resolved under one view was served to the other. The flag is now part of the options key, so each view keeps its own snapshot and a caller that alternates no longer rewrites one file every run. The flagless key is unchanged. (2) A dev build and a Release build of one source tree shared a producer identity and served each other's snapshot, which stores floats (ranks, prior weights, in-edge weights) that the two builds compute under `-ffast-math` with different inlining and LTO. The snapshot header's build field now also carries a build key: a digest of the compiler and its version, the target, the build type, LTO, PGO and every compile and link flag. A snapshot that another build wrote is refused (`why=producer` under `RIPWIRE_SNAPSHOT_STATS=1`), and the run walks, decodes and resolves as it would with no snapshot. Measured on 8 repositories, a dev build and a Release build of one commit gave equal answers and equal stored graphs: there was no observed difference, but nothing promises one. Answers without `--ignore-tests` are byte-identical. `test/warmsnapcheck.sh` gains arms KA0-KA5 and KB (KB runs when `RIPWIRE_BIN_OTHER` names the other build type).
