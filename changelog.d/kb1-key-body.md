### Changed — the first page of a `--for` answer carries the body of the symbol the question names

When a `--for` question names a symbol in backticks, page 1 now carries that symbol's definition body, right after the block that answers the question. A routed answer (`--callers` / `--uses` / `--impact` chosen from the wording) gets it as the root's last child, after the verb's rows and before a carried page; MCP `for` routes through the same code, so it carries the same element. The unrouted answer-first answer gets it directly after its first row block. The block is `<bodies of="key" shown= total= capped=>`, and each `<b t= l= p= n=>` is the `--expand` body element. Each body is whole up to 4,000 B. A longer one is cut at a line end and says so with `truncated="1" lines="1-K/T"` and `next=` the `--expand` of the rest. At most 2 bodies ride, in the question's order with rule E2's symbol first; a third keyed definition makes `capped="1"` with `next=` its `--expand`. Only bodied source definitions count: never a test file, a bodyless declaration or a namesake flood of more than 12. A body the page already carries is not repeated.

Page 1 does not count these bytes. It ends at the row it ended at without the body, so no gold row moves to a later page; page 1 is larger by the block instead. This subsumes TL1 M3 ("a late asked `<bodies>` leads the tail"), which is reverted: M3 failed its confirmation because the moved body still missed page 1.

Not applied under `--legend=first`, a token budget, `--signatures-only` or non-XML output. The body may also appear later in the same answer, in the fold or the body slot; that copy is not removed. `RIPWIRE_NO_KEY_BODY=1` turns the block off. `test/forkeybodycheck.sh` pins the routed and unrouted placement, additivity (removing the block gives the knob-off twin), pages, the 4,000 B cut, the 2-body cap, MCP parity and seven negative controls. The measured effect is in lane KB1's readout (`results/KB1_ACTREADY_1119`).
