### Changed — a warm clone pass no longer re-reads every file

The exact clone pass behind `--clones`, the `clone=` attribute of `--for`, `--partition` and the `--quality-delta` duplication kinds read every file with a function in it and normalized every body on every run, warm or cold. On cockroach that was about 9,500 files and 120 MB per warm `--for`. Each function and method body now gets a 64-bit key at parse time (a hash of its normalized token stream plus its token count), computed from the bytes the parser already holds and stored in the cache record. A warm pass groups bodies by key without opening a file, then re-reads only the bodies whose key another body shares and compares their real normalized text as before, so two bodies whose keys collide are never reported as clones. On cockroach a warm `--for` retires 15 % fewer instructions (median of three interleaved pairs, 44.95 G to 38.25 G), with the same peak memory and the same answer bytes; a cold run costs no measurable extra (envoy cold `--deps` 381 G before, 375 G after, inside run-to-run noise). The cache format moves to 50 (a function or method record ends with its key, +0.4 % cache bytes on cockroach), so an older cache is rebuilt once. Two clone groups whose first members share a file and line are now ordered by symbol id, where the order was unspecified before. New gate `test/clonepersistcheck.sh` forces two different bodies onto one key and requires that they are not reported as clones.
