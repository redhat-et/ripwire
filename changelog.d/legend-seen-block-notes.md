### Fixed — `--legend-seen=` leaves out three `--for` notes it used to re-send on every call

`--legend-seen=FILE` (and the hook that keeps FILE for a session) removes only legend text that is a dictionary entry. Three block-local `--for` notes were written after the entry table was and were never added to it, so a session that already held them still received each one whole: the `sigx` note (`sigx: a sigs row d with r above 10 …`), the unread-language hops note (`hops value_refs_unread_for_lang=L …`) and the key-body note (`bodies of=key: …`). They are entries now (`src/forlegendentries.h`), so a caller that holds one gets `legend-seen: N held` in its place, as for every other definition. The MCP session legend reads the same table.

Measured on GA1 DEV's 89 questions run as 11 one-repo sessions with the hook's harvest after every answer (240 answers, 229 of them not a session's first call), parent build against this one, each call made by both builds back to back: **15,180 B fewer over the 229 calls (0.59 % of their output; median −160 B per question with its followed pages, n = 88), 2,254 B of it on page 1 (7 of 89 cells)**. All 240 answers are byte-identical once comments, the `est_tokens=` value and the `dictv=` value are set aside, and the removed bytes are comment bytes only; file / function / body completeness is identical on 89 of 89. Without `--legend-seen` nothing changes: 89 of 89 page 1s are byte-identical. In Claude tokens (`claude-sonnet-5`, by differencing the two builds' answers, 5 answers): −60, −107, −134, −48 and −5 tokens for −160, −307, −360, −147 and −38 B.

What it does NOT do: the per-answer `legend-seen: N definitions you hold were left out …` marker and the in-place references are the disclosure and stay as they are (they are now the larger share of what repeats: 34.3 KB over the same 229 calls). The `reexports` and `shortkey` legends, which are cut per answer by present-only clauses, are still not entries.

Versions: the legend dictionary gains three lines, `dictv=b98ebdadd81dfb8a entries=1298` → `dictv=d693c8f5ff5535f1 entries=1301` on this branch's build; the recorded pair in the showcase capture and `docs/COMMANDS.md` is re-pinned from the merged build, not here.
