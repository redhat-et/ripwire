### Added — `--for` shows a package.json `bin` / `main` entry and the file it names (#451)

- `--for` manifest entry points now read the top-level `bin` and `main` fields of `package.json`, and resolve each to the file it names (its first exported function, else the file's module body); a bin is named as npm installs it (`@acme/tool` installs `tool`), and a string `bin` in a package with no `name` is no entry, as npm drops it; package.json is read for a `.js` or `.ts` row; a `package.json` inside `node_modules` is a dependency's and is not read. Gate coverage in `test/epmanifestcheck.sh` (issue #451). Thanks to @llvm-x86 for the reader and the fixtures.
- The Python, Cargo and package.json readers share one format table; Cargo and package.json targets go through one file-path resolver, and the pyproject and Cargo readers share one set of TOML helpers (headers, keys, string values, multi-line strings, so a pyproject `description = """` that spells a table is a value); a Cargo or package.json group is a manifest key, so no code is scanned for it as a loader literal, and the legend says so.
