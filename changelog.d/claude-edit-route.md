### Changed — `ripwire wrap claude` routes edits through a ranged Read and Claude Code's native Edit

Claude Code refuses a native Edit on a file it has not Read in the same session, so the pasted wiring line "apply a whole-symbol edit without a whole-file Read" could not save a Read there: an agent that followed it still had to Read the whole file before it could edit, and in our own usage the ripwire edit verbs were never called from Claude Code (0 calls against thousands of native edits over five weeks). For `ripwire wrap claude` the line now says to take the symbol's line range from ripwire, Read only that range (`offset`/`limit`), then use the native Edit, and the MCP command it prints now passes `--mcp-tools=no-edit`, a new profile that lists every tool except `replace_symbol_body`, `insert_before_symbol` and `insert_after_symbol` (about 4 KB of tools/list, roughly 1,000 tokens per session; `--mcp-tools=full` restores them). The estimate behind the change is from our own usage and a size sweep (a ranged Read plus native Edit costs about a third of a whole-file Read plus Edit at 6 KB, and the gap widens with file size); it is an estimate, not a controlled agent run. Every other agent's `wrap` output is byte-identical, and the edit verbs themselves, their CLI flags and their docs are unchanged: codex, opencode, Gemini CLI and other agents without a read-before-edit rule keep the "no whole-file Read" line and the edit tools.
