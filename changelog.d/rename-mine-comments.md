### Fixed — `--naming-calibration` no longer mines a reworded comment as a rename

The rename miner paired a removed and an added line that differ at exactly one identifier. A comment is such a pair whenever one of its words changes (`// the rows are read` → `// the rows is read`), so a grammar fix in prose was credited as a rename `are → is` and joined to any function called `is`, which moved the `naming-short` score of a pull request that touched no name. A pair whose two lines are both comment-only (a `//` or `/* … */` line, a `#` line where `#` opens a comment, or a `*` continuation line inside a block comment) is no longer a rename site. A comment after code on the same line leaves the line code, so a rename there still counts. A file in a language ripwire cannot tell comments from code in (Markdown, an unknown extension) keeps every pair. Measured on this repository's own history, the labelled pairs fall from 215 to 172; the `naming-short` rule goes from 10 fires (3 on the abandoned name, 7 on the chosen one) to 9 (3 and 6), `naming-case` and `naming-predicate` lose their one or two fires, and no rule has enough fires to be judged against its floor either way.
