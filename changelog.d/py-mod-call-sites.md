### Fixed — a Python call through a from-imported submodule is a call

`from . import mod; mod.f()`, `from pkg import mod`, `from pkg import mod as m`, `from .sub import mod` and `from .. import mod` now bind `mod.f()` to the module-scope `f` of that submodule, the way `import pkg.mod as mod` already did, so `--callers`, `--impact` and the map count these callers instead of reading zero. Before, such a call was read as a call outside the tree (external=). The binding is used only when nothing else may bind the name: the package's own namespace (a def, assignment, import of another file, star import, module `__getattr__` or `globals()` write), a rebinding in the importing file, or a second import of the name to another module each leave the call unproven, and an unproven call is declined and counted (declined_calls=), not picked. A submodule that writes its namespace dynamically, star-imports another module, or defines `f` only under an `if`/`try`, withholds the call too. A local or parameter named like the module is never the module. Not read yet: a package that re-exports `f` from another file (declined), and `pkg.mod.f()` written in full.
