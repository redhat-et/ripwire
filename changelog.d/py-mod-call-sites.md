### Fixed — a Python call through a from-imported submodule is a call

`from . import mod; mod.f()`, `from pkg import mod`, `from pkg import mod as m`, `from .sub import mod` and `from .. import mod` now bind `mod.f()` to the module-scope `f` of that submodule, the way `import pkg.mod as mod` already did, so `--callers`, `--impact` and the map count these callers instead of reading zero. Before, such a call was read as a call outside the tree (external=). The binding is used only when nothing else may bind the name: the package's own namespace (a def, assignment, import of another file, star import, module `__getattr__` or `globals()` write), a rebinding in the importing file, or a second import of the name to another module each leave the call unproven, and an unproven call is declined and counted (declined_calls=), not picked. A submodule that writes its namespace dynamically, star-imports another module, or defines `f` only under an `if`/`try`, withholds the call too, and so does any second module-scope binding of `f` there (a later `f = g`, `del f`, or `from _speedups import f`, plain or under `try`). When both `p/mod.py` and `p/mod/__init__.py` exist, the package is the module, as in Python. A from-import inside a function binds a local only, so it neither proves nor contests the module-level name. A local or parameter named like the module is never the module. Not read yet: a package that re-exports `f` from another file (declined), and `pkg.mod.f()` written in full. Also not read: an `if TYPE_CHECKING:` guard, so `if TYPE_CHECKING: from p import mod` with `else: import p.mod_rt as mod` binds `mod` to two files and the call is declined and counted (before, the runtime import was picked).

### Changed — `--for=path from A to B` keeps the path's own rows in the ranked head

In a task spelled `path from A to B`, a ranked caller of A (a resolved call, not a by-name one) that A does not itself reach within 4 hops is upstream of the asked path: it is ranked after every other scored row, keeping its own order, and the header says how many moved (`[path from: N callers of the from endpoint ranked after the path's own rows]`). B need not name a symbol. Before, a newly bound caller of A (`python -m django`'s `management.execute_from_command_line()`) could push a hop under A past the 40-row head. The MCP `for` and pack-task twins apply the same rule.
