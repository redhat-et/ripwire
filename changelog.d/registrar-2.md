### Changed — `--for` reaches registration rows when a task asks where something is defined, built or handled

The table block that ends a `--for` answer (`<lit shape="table">`) now reads three more kinds of question and site. The words defined, declared, build, builds, built, handled, turned into and get(s) to start it, but like default and handler they print only beside a row: a table row, or now a registration row. `defined` and `declared` right after not or never (`name x is not defined`, `x was not declared`) are an error message, not a question, and start nothing. A registration row is an argument of a call that says it registers: a name with a register verb (`register`, `reg`, but not beside `read`, `write`, `get`, `set`, `peek`, `poke`, `load`, `store` or `dump`: `write_reg` and `get_registry` are lookups), an adding verb (`add`, `on`, `use`, `install`, `bind`, `map`, `connect`, `subscribe`, `mount`, `attach`) before route, command or handler (`add_route`, `addEventHandler`), or, for a decorator, a name with route, command or handler. `handler(x)`, `get_handler`, `logging.FileHandler`, `run_command` and `ParseCommandLine` register nothing and are no row. That covers a Python decorator `@websocket_command({"type": "get_states"})`, `component.async_register_entity_service(SERVICE_TURN_ON, None, "async_turn_on")` spread over several lines inside a function, `registry::register_handler(x)`, and `async_reg(hass, handle_get_states)`, where the name is inside a longer one. Such a row carries `reg=` (the call up to its paren) instead of `tbl=`, because it is not a table opener and the callee's name does not prove the call registers anything. Not a call, and so no row: a declaration of the same name (a C++ constructor, a GNU-style `Registry::RegisterHandler(` definition, a JavaScript method `registerHandler(h) {`), a member of a type outside a decorator (a Rust enum's tuple variant, a TypeScript interface member), a C or C++ member-initializer list, and a statement inside a closure body (a JavaScript arrow function, a Go func literal) that sits in the arguments of a registration call. A Rust `$macro! {` inside a `macro_rules!` arm is now a table opener (risingwave's `for_all_params`). An unquoted dotted name that finds no site (`pydantic.ValidationError`) is tried again by its last part when that part is a symbol of the index (a backticked or quoted one is tried again either way); the retry lists only the rows where the last part is a quoted key (`'ValidationError': (...)`, `.method('redirect')`) and its own definition, and `tail=N` counts the sites it leaves out. Two dotted names with one last part read it once. An identifier the index has no symbol for (a type generated from a `.proto` file) is tried too. Both run after the task's other names, so they never use up those names' scans. Rows in generated and JSON files are ranked after source rows of the same nearness.

Measured on the target questions (the same arguments as the gold-blind Stage 0 rule, unsealed copies): the registration rows that rule found now appear in the answer on risingwave-03 (both natural wordings), risingwave-04, homeassistant-03, homeassistant-15 and pydantic-03, and kubernetes-01 prints no block. Gate `forregrowcheck` covers Rust, Python, TypeScript, Go, C++ and JavaScript fixtures: the declarations, members, closure bodies and callee names above (each with a twin that must stay a row), a definition named like a handler, a closed call, calls not named for a registration, the dotted-tail retry on a common word and on a quoted key, and the error-message cue.

What it does NOT do: it does not prove a call registers anything (the row quotes the call, nothing more). It does not follow a registration through a constant (`SERVICE_TURN_ON = "turn_on"`) or a Go map index assignment (`storage[resource+"/log"] = …`). It reads at most 4 lines and 512 bytes back for the open paren, so a registration call opened further up is no row, and the table legend says so; a missing `reg=` is no claim. An unquoted dotted name whose last part is no symbol of the index is not retried (a backticked or quoted one is). Parens inside strings and comments are skipped, which is a read of the nearest lines, not a parser.
