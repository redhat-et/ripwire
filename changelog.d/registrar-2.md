### Changed — `--for` reaches registration rows when a task asks where something is defined, built or handled

The table block that ends a `--for` answer (`<lit shape="table">`) now reads three more kinds of question and site. The words defined, declared, build, builds, built, handled, turned into and get(s) to start it, but like default and handler it prints only beside a row: a table row, or now a registration row. A registration row is an argument of a call named for a registration (reg, register, route, command or handler, read as whole words of the callee's name). That covers a Python decorator `@websocket_command({"type": "get_states"})`, `component.async_register_entity_service(SERVICE_TURN_ON, None, "async_turn_on")` spread over several lines inside a function, and `async_reg(hass, handle_get_states)`, where the name is inside a longer one. Such a row carries `reg=` (the call up to its paren) instead of `tbl=`, because it is not a table opener and the callee's name does not prove the call registers anything. A Rust `$macro! {` inside a `macro_rules!` arm is now a table opener (risingwave's `for_all_params`). A dotted name that finds no row (`pydantic.ValidationError`) is tried again by its last part, and an identifier the index has no symbol for (a type generated from a `.proto` file) is tried too. Both run after the task's other names, so they never use up those names' scans. Rows in generated and JSON files are ranked after rows in source files.

Measured on the target questions (the same arguments as the gold-blind Stage 0 rule, unsealed copies): the registration rows that rule found now appear in the answer on risingwave-03 (both natural wordings), risingwave-04, homeassistant-03, homeassistant-15 and pydantic-03, and kubernetes-01 prints no block. Gate `forregrowcheck` covers Rust, Python, TypeScript and Go fixtures, plus a definition named like a handler, a closed call, and calls not named for a registration.

What it does NOT do: it does not prove a call registers anything (the row quotes the call, nothing more). It does not follow a registration through a constant (`SERVICE_TURN_ON = "turn_on"`) or a Go map index assignment (`storage[resource+"/log"] = …`). It reads at most 4 lines and 512 bytes back for the open paren, and it does not tell apart parens inside strings or comments.
