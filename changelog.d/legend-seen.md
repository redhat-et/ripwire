### Added — `--legend-seen=FILE`: an answer leaves out the legend definitions you already received

A CLI agent makes several calls a session and was sent mostly the same legend definitions every time; an answer-first `--for` page 1 is about 12 KB of rows plus about 4 KB of legend. `--legend-seen=FILE` names, one 16-hex hash per line, the dictionary entries the caller already holds, and the answer leaves exactly those out. `ripwire --legend-dict=seen` reads answers you received on stdin and prints the hashes they carried, so the file is built from what actually reached you (`| head` included).

- **Per definition, no tiers.** Nothing to read first and nothing to refuse — unlike `--legend-have=`, whose taught tiers measured break-even on the same sessions (+2.6 % at 5 calls, −0.7 % at 10).
- **Lossless.** Rows, CDATA and every root attribute but `est_tokens=` (repriced to the bytes delivered) are byte-identical. Each reduced comment says `[legend-seen: N held]` where it left definitions out, and one comment names the `dictv=` of the dictionary that holds them all.
- **A hash is of the definition's text**, so a file written by another build only matches definitions that did not change. A missing, unreadable, oversized or corrupt file serves the whole answer and says so on stderr — the flag never turns a call into a failure. Refused: an empty value, `--legend-have=`, `--legend=full|dict`, the server transports.
- **`--for` is reducible now.** Its 99 legend pieces — the trailing document legend, the page clause, the `est_tokens=` sentences and the block-local `ripwire for X` legends that travel with their sections, split at their present-only clauses so a cut-down legend is still made of entries — are dictionary entries (`versions.md`).
- **Claude Code does it for you.** `skills/install.sh --hook` registers `hooks/ripwire-legend-seen.sh` (PreToolUse/PostToolUse on Bash, SessionStart/PreCompact): it inserts `--legend-seen=<session file>` after the binary word and records what each received answer carried, per session and per agent, forgotten on resume, clear and compaction. It never sets a permission decision. `RIPWIRE_LEGEND_SEEN=0` turns it off. The MCP server is unchanged (`--mcp-legend=session` already sends each definition once); its `for` sessions now also stop re-sending the sibling-demote comment once it is served.

Measured on lane P4's replayed sessions (flake8, fzf, tmux; the hook driven as Claude Code drives it; the inserted flag text counted against it), against today's default: **5-call sessions −7.7 % (88,589 → 81,737 B, n = 15 calls), 10-call −10.7 % (120,565 → 107,705 B, n = 30)**; every one of the 45 answers byte-identical outside its comments and `est_tokens=`, and every attribute the default answer defined still defined in the reduced answer or in a held line. A later `--for` page 1 in a session saves a median 2,729 B (17.8 %; 2,085–3,357 B, n = 16 over 8 corpora). A call whose legend shares nothing with what came before pays the flag (about 110 B) for nothing.
