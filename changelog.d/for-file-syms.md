### Added — `--for` names the shown files' other symbols (`<syms>`)

A `--for` answer often shows the right file and the wrong symbol of it: a neighbour ranks on body or doc text while the function the task needs sits a few lines away, unnamed. The answer now ends with `<syms>`, a few symbols of its first six shown files that it does not name anywhere, one row each (`n=` the owner-qualified name, `p=file:line`, no body). They are leads to read, not the answer. "Does not name" is read off the bytes the run emitted before the block (every section and every trailing block: declaration rows, the graph verb, re-exports, the short-key ladder, the literal anchor, dotted strings, `--with-graph`), by the spelling the answer prints: a name with its `#`, `$`, `@` or `~` mark or its `?` or `!` ending (`#addRoute`, `$tryShow`, `valid?`) is looked up as spelled, and a symbol a shown row stands on is never offered. A C or C++ header declaration and its definition elsewhere are one row (the definition's). `by="name"`: the name shares a task word. `by="callee"`: a definition named like one of the first eight `<d>` rows calls, in the index's graph, a definition named like it: names resolve at both ends (a row's name is what the answer gave). The row is plain only when the shown row itself calls that very definition over an evidence-bound edge; `prov="split"` marks one arm of a split call; `via="name"` every other row (a namesake's call, a call to a namesake, or one bound by name alone). A row in a test or fixture file or scope carries `test="1"`. Three rows per rule, six files, eight head rows: the legend says so, and the open tag prints `files=` / `head=` only when fewer were read, and `name_total=` / `callee_total=` / `files_total=` only when a cap cut (the cut rows are counted, not listed). Present only when a candidate scores. Outside `est_tokens`; under `--token-budget` or `--max-tokens` the block is held (`held="budget"`, `next=` the same call without the budget, with the ranking flags the call had: `--no-route`, `--anchor`, `--pack-top-n`), with a one-line legend of its own, and a run that could not buffer its bytes, or whose buffer failed to flush or read back whole, prints `<syms held="uncaptured"/>` and a line on stderr (the second also exits 1: the answer may be short). The block's legend comment sits right before it and spells every attribute the block prints as `name=`, in both legend dialects (a compile-time check holds the two strings to one attribute list); `legendcoveragecheck` reads a legend comment that immediately precedes a trailing block (`<syms>`, `<decl_rows>`, `<graph_verb>`) for that block's own elements. On the MCP `for` surface the block is the last thing before `</ctx>`, as on the CLI. XML only: `--json`, columnar, multi-root and the ranking-candidates export carry no block. `RIPWIRE_NO_FILE_SYMS=1` turns it off.
