### Added — `--for` names the shown files' other symbols (`<syms>`)

A `--for` answer often shows the right file and the wrong symbol of it: a neighbour ranks on body or doc text while the function the task needs sits a few lines away, unnamed. The answer now ends with `<syms>`, a few symbols of its first six shown files that it does not name anywhere, one row each (`n=` the owner-qualified name, `p=file:line`, no body). `by="name"`: the name shares a task word. `by="callee"`: a definition named like one of the first eight `<d>` rows calls, in the index's graph, a definition named like it: names resolve at both ends (a row's name is what the answer gave). The row is plain only when the shown row itself calls that very definition over an evidence-bound edge; `prov="split"` marks one arm of a split call; `via="name"` every other row (a namesake's call, a call to a namesake, or one bound by name alone). Three rows per rule; when the cap cuts a rule, `name_capped="1" name_total=` / `callee_capped="1" callee_total=` count its candidates, and `files_capped="1" files_total=` the shown files past the six read. Present only when a candidate scores. Outside `est_tokens`; under `--token-budget` or `--max-tokens` the block is held (`held="budget"`, `next=` the same call without the budget). XML only: `--json`, columnar and multi-root answers carry no block. `RIPWIRE_NO_FILE_SYMS=1` turns it off.
