### Changed — `tested=` says reached, not asserted; `cbo=` says out-coupling; `--arch` says UNKNOWN over files it never read

- **`tested=`.** The legend now says a test *reaches* the row over call edges, and that reaching is not asserting. A test that calls a function need not check what it returns: Veritas (arXiv 2610.33708; 11 Java projects, 51,382 branch outcomes) found 18% of covered branch outcomes could change with no test failing. The predicate is unchanged; only the reading moved, in the compact and full dialects alike (`<s tested=1>`, `<d tested=1>`, the columnar `<tested>` column).
- **`cbo=`.** The `--metrics` compact legend called it "coupled types". It is out-coupling: the distinct in-repo targets a symbol calls or composes. `in=` is its in-coupling, and the two load as separate factors (Arif, Kuutila & Ralph, arXiv 2609.20411), so the reading keeps them apart. No score in the tree sums them today; `test/metriclegendcheck.sh` now holds that.
- **`--arch` observation qualification.** A file whose imports this build never reads (a `no_file_edges=` language such as Go or Java, or a code extension it does not index, such as `.scala`) on a rule's FROM side used to leave that rule silently passing. In `--baseline` mode the run exited 0 with no stderr line at all. `<arch>` now carries `unqualified=N`, each such rule gets a `<rule text= unqualified= verdict="unknown">` row, and stderr says the rule is UNKNOWN in every mode. Exit codes are unchanged (2 on a new violation, 0 in the baseline modes). The attribute and the rows are present-only, so a tree with no such file answers byte for byte as before.
- **Docs.** `docs/METHODOLOGY.md` §9.3 and the `src/quality.h` bar comments say the size and complexity bars are delta heuristics, not smell detectors. They also record the one human-labelled length reference (MLCQ Long Method ≥ 26 lines, MCC 0.777, arXiv 2611.01636, single author). No default changed.

Gates: `test/metriclegendcheck.sh`, `test/archunqualifiedcheck.sh`.
