### Fixed — C/C++ file edges: a quote include resolves at the include roots a build passes (#478, thanks @jflowers)

A quote `#include "source/common/http/utility.h"` was probed only in the includer's own directory, so a tree that includes by root path had almost no file graph: Envoy resolved 289 of its 34,973 include edges, and `--deps` called it `shape="horizontal"`. On a miss in the includer's directory, a quote include is now probed at the repo root, at each `include/` directory beside the includer's directory or an ancestor (nearest first, the same module-root rule the Python src-layout fix uses), and at a root `src/`. Each root is a shape a build file in the test corpus passes as `-I` (the repo root: Envoy's Bazel, htop's automake, tmux's `-iquote .`; `include/`: waybar's meson, CPython's `Modules/_hacl`; root `src/`: ninja's fuzzer build); `source/` and `lib/` bound nothing and are not probed. The includer's own directory still wins, the hit must be unique across the roots, and a name two roots both hold draws no edge and is counted in `imports_unresolved=` with `graph_partial="1"` on `--deps` and `--arch` (and `imports_unresolved=` on `--impact`). Angle includes are unchanged, so `<string.h>` never binds a sibling `string.h`.

Measured with @jflowers' ground-truth method from #478 (exact afferent and efferent coupling per directory, and mean absolute error, against an independent truth): Envoy goes from 289 to 34,196 of 34,973 static-truth edges, directories exact on Ca/Ce from 41 % / 1 % to 96 % / 92 %, MAE 9.62 to 0.21; htop, tmux and ninja reach 100 % / 100 % with MAE 0. A second oracle, the compiler's own `clang -E -H` with the `-I` flags read by hand from each build file, finds 0 false edges on htop, tmux, ninja and waybar, and a stratified hand sample of 30 Envoy edges finds 0. Envoy's health line now reads `shape="vertical"`; `--impact=source/common/common/assert.h` lists 614 importers where it listed 0, with its directory and test rollup.

What it does NOT change: the call graph. The C/C++ call narrow (Rule 3's include evidence) keeps the includer-directory resolution, so no call edge moves: on 61 graded C/C++ questions (Envoy, htop, tmux, ninja) 58 answers are byte-identical and 3 change only in file-graph counts, two `--impact` importer counts on tmux (149 to 157) and one `--defs` count on Envoy (79 to 78: `MainCommon::main`'s bodyless declaration now folds into its definition, because `main_common.cc` includes its header by root path); no graded item moves. With the root edges, Rule 3 bound about 2,060 more Envoy call sites without a hedge, and a hand read put about 300 of them on a wrong in-tree namesake (`std::format` on a local `fmt.h`, `absl::Span` on a local `class Span`). The two re-couple once external-qualified calls are vetoed. Still unresolved: the 2 % of Envoy edges written as a path suffix (`"utility.h"` for `source/common/http/utility.h`) and angle includes of in-tree headers; both need the build's own `-I` flags.
