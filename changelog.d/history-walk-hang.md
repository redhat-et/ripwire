### Fixed — a history walk no longer downloads, and no longer hangs

- On a long real history, `--for`, `--metrics` and `--exemplar` waited on `git log --name-only` with no limit: past 3600 s on a 310 K-commit ClickHouse clone, and on a blobless clone git fetched blobs from the network as it went (`.git` 15 GB to 33 GB). Now:
  - No git command of ripwire's lazy-fetches on a partial clone: each carries `GIT_NO_LAZY_FETCH=1` (git 2.45 and later) and a closed `GIT_ALLOW_PROTOCOL` (git 2.6.1 and later), as a prefix on that command only. They are not set in ripwire's own environment, so the command `--run-trace` runs, and any other child that is not git, sees the environment you gave ripwire; and the clone of a URL root uses your own `GIT_ALLOW_PROTOCOL` and `protocol.*.allow` as `git clone` would. Versions are from git's source at the tags (`environment.h`, `git.c`, `transport.c`); only git 2.50.1 was run, an older git is simulated by a shim. A verb that truly needs an absent blob says so: `--quality-delta=REF` refuses naming the partial clone and the `git archive <sha> >/dev/null` that fetches it yourself, `--pr-context` lists the changed files from the trees (a dirty tree too) and refuses when it cannot, `--stray-content` reports a branch it could not read as `unknown`, never `merged`.
  - The walks carry `--no-renames`. Rename detection was the only thing that read blobs. It changes one thing: a rename commit now also lists the path it left, which matters only when that path exists again at HEAD (whole history: textual 5 of 354 such paths, hono 3 of 286, tmux 1 of 23).
  - Every record walk has a budget, 20 s or 200 K commits (`RIPWIRE_GIT_WALK_SECONDS`, `RIPWIRE_GIT_WALK_COMMITS`, 0 = none). A cut keeps the newest commits and says so: `history_unread="1"` on documents with `churn=`/`amp=`, a `history_cut` comment and stderr line on every other CLI verb, and a `_history_cut` envelope note on an MCP answer. Where the clock cut a walk, the prefix it reached moves with machine load, so two runs can differ; the cut is cached until HEAD moves except under `--no-cache`, and a clock cut under about 1,000 commits is not cached. ClickHouse `--for`: 3600 s and unfinished, now 50 s.
