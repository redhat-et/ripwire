### Changed — `--for` answers a question that names one symbol with a tiny named-location answer, on by default (#742)

When a `--for` question names one symbol that resolves in the top 8 ranked rows with `confidence="high"`, and the question asks for no route, call path, breadth or indirection, the answer is now about 1-2 KB: the root, the act line, the ranked `path:first-last name` rows of that symbol (`<sigs>`), an `<edges>` line naming up to 4 of its calls into and callers from other non-test files, and one `<more next=>` call that returns the full page. The root says `shape="tiny"`. A question whose answer spreads further (a `<dispatch>`, a re-export hop outside the defining files, more than 6 other-file callers, a cut callers block with no edge to name, an ALL-CAPS constant) keeps the full page. Only the CLI `--for` default page takes the shape: an explicit `--page-bytes`, a later page, `--token-budget`, `--max-tokens`, `--detail`, `--signatures-only`, `--auto-bodies`, `--sections`, `--compress`, `--with-graph`, `--rows=elements`, `--legend=first`, `--json` and MCP `for` are unchanged.

To turn it off, set `RIPWIRE_TINY_SHAPE=0`: every answer is then byte-identical to the full page (gate `test/tinyshapecheck.sh` (I)). `--version` now names the posture as `tiny=on` or `tiny=off`.
