### Fixed — C++ calls through smart-pointer locals, parameters and aliases reach the interface tier instead of every namesake

A C++ local or parameter declared as a `std::unique_ptr<T>` / `std::shared_ptr<T>`, or as an alias of one (`Event::TimerPtr t`, `const CodecPtr& c`, `typedef std::shared_ptr<Widget> WidgetSharedPtr`), was untyped: `t->enabled()` was matched by name against every in-tree `enabled`. Such a declaration is now its pointee through `->`, as a member written that way already was (lane iface-peel): a concrete pointee is a typed edge, an interface declines `gate="iface"` with its implementors counted. A pointer to the smart pointer (`CodecPtr* p`), `.` on it (`c.reset()`), an alias two namespaces declare for different pointees, a template alias (`Ptr<T>`), `c.get()->m()` and `(*c).m()` keep the previous reading. The interface tier also counts an implementor defined out of line as a nested class (`class Mgr::RangeTimerImpl : public Timer`, envoy) and one that inherits its body through a sibling base (`ConnectionSocketImpl : SocketImpl`); a member typed as an interface whose split holds one unproven body while another definition shares its name now declines `cands="1"` instead of listing every same-named method by name (a lone definition keeps its one by-name row). Caches are rebuilt once (parser version bump).
