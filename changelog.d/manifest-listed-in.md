### Added — `--for` shows the manifest lines that list a shown file when the task adds something new

When a `--for` task is a creation task (it says new, add, register, plugin or extension as a word — not inside an identifier such as `Plan::AddTarget`) and a build, package or registry manifest at the root or in a directory above the ranked rows lists two or more of their files (a list of the exemplar's siblings, not a single `"main"` entry), the answer now carries those lines after the file tail: `<listed p= of= by=path|dir>` with each line byte-exact as `<ln l=>`, preceded by the less-indented line it sits under (automake's `dist_tmux_SOURCES = \`, package.json's `"./timing": {`, a Bazel `EXTENSIONS = {` dict). Read: Makefile.am (a configure-written Makefile beside it is skipped), Makefile, CMakeLists.txt, meson.build, BUILD/BUILD.bazel, `*.bzl`, package.json, jsr.json, deno.json, and Cargo.toml (CODEOWNERS is ownership, not a listing, and is not read). `by="path"` names the file, `by="dir"` only its directory (two or more whole path segments, so `middleware/log` never matches `middleware/logger`; make, CMake, meson and Bazel BUILD files are matched by file path only, so a dependency label is not a listing); `also=` lists the other shown files the same manifest names. Files under vendor/, third_party/, node_modules/ and bower_components/ are vendored and skipped. Comment lines, glob or variable listings and lists keyed by a command or option name (man pages, docs indexes) are not matched. Default regime and XML only; `RIPWIRE_NO_LISTED_IN=1` turns it off. On "new tmux command" the answer now prints the Makefile.am sources list (+0.5 KB), on hono's "new middleware" the package.json and jsr.json `exports` entries (+1.3 KB), on Envoy's "add a new HTTP filter extension" `extensions_build_config.bzl` and the extension's BUILD file; answers whose task has no creation word are byte-identical.

A name counts as listed only where the manifest resolves it from its own directory, inside one stanza: `legacy/x.c` is not `x.c`, a subdirectory manifest's root-anchored `$(top_srcdir)/x.c`, `${CMAKE_SOURCE_DIR}/x.c` or Bazel `//:x.cc` is not its own `sub/x.c` (and is not listed), another package's `package.json` does not list this package's directory, an `exclude = [...]` / `list(REMOVE_ITEM ...)` list and a `#[[ ... ]]`, `/* ... */` or trailing `#` comment name nothing, and a second name counts as a sibling only in the same top-level stanza. A manifest above the crawl size ceiling is not read. The legend says the block is not exhaustive. The two caps on what is read (a directory's `*.bzl` files past the eighth, shown files past the sixteenth) are disclosed on the first `<listed>` as `files_capped="1"`; an answer with no `<listed>` makes no claim, so there is nothing to disclose.
