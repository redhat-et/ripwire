### Added — `--for` on an add-a-new-X task names X's family: the existing siblings a new one joins

A task like "add a new builtin scalar SQL function", "I need to write a scheduler plugin that lives in the tree" or "I want to add a new dialect" now ends with an `<exemplar_family>` block before `</ctx>`: how the existing X are grouped (`rule=`: implementors of one base or interface, the entries of one registry map or dispatch table, typed instances of one C/C++ struct type, items under one attribute macro or decorator, or classes whose names end in X in one directory), the shared `key=` and where it is defined, `matched=` (the words of the task found in `key=` or `scope=`: why this family won, and a family that matches few of them is a weak guess), the directory the family was narrowed to (`scope=`), its size (`n=`, test, sample, example and benchmark code excluded) and up to four members, the typical one first (nearest the median size). Go registries and C vtable instances are found even where the implementors list is empty (Go has no `implements`; a C `const MeterClass X_class` is not a subclass). The block is present only when a family resolves, the answer before it is unchanged, a token budget holds it (`held="budget"`), and the MCP `for` tool prints the same element. New gate `test/forexemplarcheck.sh` pins one fixture per rule (C typed instances, Go and C++ registry maps, a Rust attribute macro, a TS interface, a Python subclass), the wordings that fire and the ones that stay silent.

The same block now carries a `<touch_list>`: the files outside the members' own that mention at least half of the family, ranked by share — where existing siblings are registered or listed (a name constant list, a defaults list, an exhaustive `match`, a package `__init__` or barrel `index.ts`), each with `share=` (the distinct member names it mentions out of the distinct names, or with `by="stem"` the distinct file stems out of the distinct stems: a name or stem several members share counts once, so one shared word never credits every member), the line to copy (the first naming the typical member; an import or a comment only when no code line does) and its text, cut at 120 bytes with `cut="1"`. Names are matched with snake, Camel, kebab and UPPER forms folded, plus each member's registered name and file stem. Test, docs, vendored, generated, frozen and baseline files are not read; more than five listing files print five rows with `total=`, `shown=` and `capped="1"`. On the kubernetes scheduler-plugin task it lists `apis/config/v1/default_plugins.go` and `plugins/names/names.go`; on the risingwave scalar-function task `scalar/mod.rs`, the frontend's `expr/pure.rs`, the optimizer's `strong.rs` and the binder's `builtin_scalar.rs`.

The block's legend follows `--legend`: the short form by default (`--legend=compact`), the full prose with `--legend=full` and in the MCP `for` tool; both define every attribute. A decorator is matched whatever its case (`@Widget()` for a task about a widget), a function's parameter list is never read as registry entries, and the name-ending rule names classes only (a function named `execute_command` is not a sibling of a command), needs them in at least three files (one file of `*Options` interfaces is a type list) and not only in `.d.ts` declaration files, and, because names alone are the weakest grouping, prints `grouping="affix-only, weak: verify one m before copying"` on its own family line, so the row hedges itself without the legend.
