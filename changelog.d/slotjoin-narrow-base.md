### Changed — a served `--for` builds the question-independent part of the narrow value index once per call, not three times

A `--for` builds the narrow value index (the slot splice's `slot_by=` / `slot_fields=`, the by-bind file rows and the bind ranking each build one), and each build walked every reference of the model and resolved every slot store, registrar argument and slot call again, although only the values that name one of the shown functions read the question. On the model the warm snapshot identifies, the empty question's narrow index is now built once per process, on the first use, and each question copies it and adds its own named values. Any other model (an `--ignore-tests` filter, `--no-cache`, `RIPWIRE_NO_VERBFS=1`) builds as before. Every answer is byte-identical; in a plain (non-release) build every derived index is also checked equal to a fresh one. `RIPWIRE_STATS=1` prints one `[valueref] narrow_base=` line per narrow index. New gate `test/slotbasecheck.sh`.
