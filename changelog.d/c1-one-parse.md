### Changed — one parse cache blob serves every verb (ONE-PARSE, #729)

The warm-by-default parse cache kept two blobs per tree, one per verb class (`ripwire-<key>-lean-c…` for the map and the navigation verbs, `ripwire-<key>-rich-c…` for `--for`, `--exemplar`, `--metrics`, `--uses`), so a `--for` straight after a map parsed the whole tree again. Since cache format 56 every record is the rich one, whichever verb wrote it; a lean verb drops the rich-only rows (value-use references and def subtoken stats) after reading, so both classes share one blob, `ripwire-<key>-c56p<parser>.bin`. `test/cachesplitcheck.sh` holds that the lean model built from the shared blob has every fact family the size a lean parse gives it, and that map, `--deps`, `--callers`, `--expand` and `--for` answer byte-identically to `--no-cache` after either order. `--index-out=BASE` now parses once and writes the same blob under both of its names. The first run after upgrading parses once; old `-lean-`/`-rich-` blobs are evicted as another build's.
