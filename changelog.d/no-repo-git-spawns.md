### Fixed — an MCP edit on a directory that is not a git repository no longer starts git children that can only fail

MEASURE-M5 profiled the MCP edit path on a one-file corpus that is no repository. A PATH shim counted 8 git children on a root's first edit and 4 on every later edit. They were `diff --numstat HEAD`, `diff --name-only HEAD HEAD` and `rev-parse --verify HEAD` from the changed-file mask, built once for the pre-edit index and once for the post-edit re-index. The others were a `config` read on the root's first sighting and `rev-parse --verify HEAD` from the edit's contract-vs-HEAD check. Every one answered "not a git repository", and together they cost about a third of each 265–314 ms edit.

Git finds a repository by walking up from the directory to the first `.git` entry or bare-repository-shaped directory, unless `GIT_DIR` names one. `src/gitrootfacts.h` reads the same facts with `realpath` and two `stat` calls per level. When the root's real path holds neither entry at any level and `GIT_DIR` is unset, git provably cannot find a repository, so the mask builder (`gitDiffChangedMaskNumstat`) and `gitRepoHasHistory` return their existing non-repo answer without asking git. The facts are re-read on every call, so a long-lived MCP session notices `git init` on its next call. The answer is unchanged: the edit still reports `edit_check` status `no-baseline`.

`gitRepoToplevel`'s per-directory memo used to assume a directory's top level cannot change under a running process. That is false for a long-lived server. Each memo entry now keeps the discovery facts it was computed under, and git is asked again when they change: a `.git` appears, disappears or is rewritten at any level, or `GIT_DIR`/`GIT_WORK_TREE`/`GIT_COMMON_DIR` changes. `hasEnclosingGitRepo` now reads the same walk instead of its own copy.

The proof is conservative. A stray file named `HEAD`, an unresolvable root, `GIT_DIR` set, or a Windows drive path all make it decline, and git is asked as before. "A repository with no commit yet" is not cached, because its first commit changes nothing this check reads reliably. Gate: `test/norepogitcheck.sh`.
