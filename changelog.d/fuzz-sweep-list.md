### Fixed — `test/fuzz/run.sh` sweeps every registered grammar fuzzer, read from CMake (#765)

The sweep's grammar list was typed into `run.sh` and had fallen behind: it ran 17 of the 25 `ripwire_fuzz_<name>` targets that `CMakeLists.txt` builds, so `toml`, `yaml`, `csharp`, `c`, `php`, `lua`, `gdscript` and `proto` were built and never fuzzed. `run.sh` now reads the NAME of every `add_ripwire_fuzzer( NAME LANGUAGE KEY )` line, so a new grammar is swept once it is registered; `run.sh --list` prints that list, and a third argument or `RIPWIRE_FUZZ_GRAMMARS="lua proto"` narrows a run (a name with no such line is refused, exit 2). `proto` gains the seed (`test/fuzz/seeds/proto/valid`) the other 24 already had. `test/g1configcheck.sh` now compares `run.sh --list` with the CMake lines, checks the override, checks a seed for every registered grammar, and takes its configured-model expectation from the same lines (it still said 24). Against the old `run.sh` the new arm fails naming exactly those eight grammars. What it does not mean: nothing here says the eight newly swept grammars are crash-free; this change was not run under a libFuzzer build.
