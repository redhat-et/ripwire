### Fixed — a refused file no longer rewrites the whole cache on every warm run

A file the nesting guard refuses (a JSON, YAML, Markdown or Kotlin file nested past its ceiling) is stored in the cache as unknown on purpose, so every warm run re-reads it, re-refuses it and lists it again under `--skipped`. That re-read also marked the cache changed, so the whole cache was serialized and written again on every warm run of a tree holding one such file; on envoy that was a 146 MB write per run. A cache miss that ends before the parse (unreadable, binary or refused) now marks the cache changed only when the cache's record for that file differs from the one this run would write. A file that becomes refused, or stops being refused, still updates the cache. The refusal note and the `--skipped` row are unchanged, and the cache format is unchanged. `RIPWIRE_CACHE_STATS`' `reparsed=` no longer counts an unchanged refused file. New arms (w1)-(w5) in `test/savecachecheck.sh` pin both directions.

Not covered yet: a file whose extraction was partial is still stored as unknown with its facts, so a warm run re-parses it and rewrites the cache as before. None of the seven large repositories measured has one.
