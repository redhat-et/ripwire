### Changed — an in-process re-ingest no longer recompiles the tags queries the process already holds

Every ingest compiled the `tags.scm` query of each grammar its changed files needed, even when an earlier ingest in the same process had compiled it already. A one-shot CLI run ingests once, so it never paid twice, but a long-lived MCP server does: each applied edit ingests before the write and again after it, and every one of those ingests recompiled the cpp query and then deleted the copy it displaced. On 60 applied edits to one-file corpora in one server, an edit took 381–408 ms before and 130–197 ms after (a dev build at load 23–35, so read the ratio, not the absolutes), and `mcpframehonestycheck` went from 94 s to 36 s. The process-wide query cache is keyed by grammar, and each grammar names one query (now a `static_assert`), so the prewarm now compiles only the grammars the cache lacks. A grammar whose compile failed is cached as empty and is compiled again, so its stderr disclosure repeats on every ingest as before. Answers are byte-identical: `test/querycachereusecheck.sh` compares a two-edit MCP session against the old recompile path (`RIPWIRE_FAULT_QUERY_RECOMPILE=1`, non-NDEBUG builds) and reads the new `RIPWIRE_STATS` line `ripwire: stats query-reuse ingest=K needed=N held=H compiled=C`, which every ingest after a process's first prints.
