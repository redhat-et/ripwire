### Fixed — `--for` anchors the symbol a subject names, and says when no source defines it

- `--for`: a descriptive subject that names ONE function can anchor it. Where the answer on that function alone prints its body and its callers (one function in the whole index, a body that fits the single-anchor allowance, at least one caller), the route trades its ranked map for the function, and `route=` lists the plain words beside it under `dropped:` (`transformNodes new parameter`, `how does X work`). Every other call keeps the route and answer it had, the low-confidence note below aside: a subject that names several symbols, a type, or a function that fails that test, and a call that prints no body or no callers (`--json`, `--detail`, `--signatures-only`, `--token-budget`, `--format=candidates`, the `--limit`/`--offset` file page, an explicit `--pack-budget-bytes`). A conceptual route whose descriptive subject names a function carries `<callers by="subject">` on top. The MCP `for` verb, which serves signatures only, keeps its map.
- `--for`: `confidence="high"` on a name-exact route needs a source definition behind the anchor. An anchor only a test, doc or data file defines reads low, and `route=` says why. A plain word never vouches for a subject that spells a name: `max_concurrent_queries read`, whose key lives in a data file, reads low although `read` is defined in source.
