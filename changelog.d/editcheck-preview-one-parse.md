### Changed — the first `--edit-check` after a commit no longer re-parses the whole HEAD tree, and the `--dry-run` preview parses the edited file once

`--edit-check` (plain, or as the `--edit-payload FILE --dry-run` preview) and `--quality-delta` compare the working tree with a baseline built from git HEAD. That baseline's parse cache was named by the HEAD commit, so the first such run after any commit found no cache and re-parsed every committed file. On this repo (4,996 files), a one-file commit gave `cache-stats reparsed=4991 reused=5`. Each cache record is checked file by file when it is loaded (parser version, content hash, and the file's ctime, which an extraction cannot forge). So a record from the previous commit is exactly right for every file the new commit did not change. The baseline now starts from the newest cache of the same repository and `--exclude` set, and re-parses only what the commit changed: `reparsed=3 reused=4993` after a 3-file commit. The older cache is copied, not moved, so it stays valid for its own commit. With no older cache (a first run, or a fresh cache directory) nothing changes.

The preview also used to parse the edited file twice: once with the payload spliced in, and once as it is on disk, only to count its parse errors before the edit. The run's own index already holds that count, so the preview now reads it from there. It still parses the on-disk file when the index cannot vouch for the count: never measured, or measured on bytes of a different length. With `RIPWIRE_STATS` set, the preview prints `[stats] edit-preview parses=N error_baseline=index|parse`.

Answers are unchanged. `test/editpreviewwarmcheck.sh` holds the warm preview byte-identical to a fully cold one, and to the post-apply `--edit-check`, on three fixtures: a contract change, no change, and a new caller break. It also holds that identity on the first run after a commit.

Measured on a Release build, medians, on a machine under a load average of about 40 on 18 cores (not a quiet machine, so read these as wall clock under contention):

- **First preview after a one-file commit, this repo (n=5):** 11.63 s to 8.20 s wall, 22.73 s to 14.09 s CPU. An agent hook measured the first plain `--edit-check` after a new HEAD at 10.11 s with a warm cache. Its 15.36 s preview was a cold-cache run, which this change does not speed up (below).
- **Warm preview, this repo, target `src/graph.h` (1.2 MB) (n=10):** 0.945 s to 0.78 s wall, 1.335 s to 0.995 s CPU, against 0.32–0.37 s for a plain `--edit-check`. The second parse of `src/graph.h` was about 0.33 s CPU. The rest of what the preview adds is about 0.22 s, mostly the call graph rebuilt over the edited tree.
- **Warm preview, envoy (`source/common/http/utility.cc`, n=5):** 9.19 s to 7.14 s wall, which is within this machine's noise, and 2.85 s to 2.77 s CPU, against 2.12–2.49 s for a plain run. A 65 KB file's second parse is small. Rebuilding the call graph over the edited tree is the preview's cost here.
- **Warm preview, llvm (`llvm/include/llvm/ADT/StringExtras.h`, n=5):** 33.31 s and 37.56 s wall, 38.25 s and 38.08 s CPU: no change. A plain run takes 4.62–5.24 s. Nearly all of the preview is the call-graph rebuild over the edited tree (4.36 GB peak). Reusing the warm graph is not part of this change.
- **Cold preview (a fresh cache directory):** no change outside noise. This repo (n=3): 11.92 s and 10.12 s wall. Envoy (n=3): 21.47 s and 25.03 s. llvm (n=1): 287.30 s and 339.08 s.
