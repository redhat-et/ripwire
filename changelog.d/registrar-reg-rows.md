### Added — `--for` joins a registry key to what is registered under it (Python signals, TypeScript providers)

A compact `--for` answer now carries a `<reg key= p= n= tests= by= consumers=>` row with up to four `<r sym= p= [as=]/>` registrations when the question is about a registry: Django-style `request_finished.connect( close_caches )` / `signals.request_finished.connect( … )` for a module variable `K = Signal()` whose `connect` stores its parameter into a container of `self` (the registrar is checked structurally, never matched by the name `connect`), and Angular/NestJS provider records `{ provide: TOKEN, useClass: X }` (`as=` names the field: `useClass`, `useExisting`, `useFactory`, `useValue`). The key is resolved through the site file's imports (and up to three re-export hops) to one definition, or there is no row. A row prints only when the question names the key or a registered name, or a shown ranked row consumes the key (`signals.request_finished.send( … )`'s function, a constructor with `@Inject( TOKEN )` or its class), and only with two or more non-test registrations (one is enough beside a shown consumer); test registrations are counted in `tests=`, not listed. The legend states it is a static fact at the site (the call as written; conditional or dynamic registration may exist; `sender=`/`weak=`/`dispatch_uid=` are not read; not proof a receiver ran), that `n=` is a floor (decorator, keyword-argument, alias, `forwardRef` and unresolved-import registrations are not counted), and defines `consumers_more=`, `reg_more=` (keys past the two-row cap) and `cut=1` (a re-export chain over three hops was not followed). A name a function writes locally (a parameter, a loop variable, an assignment) is never keyed to the module-level definition, `import pkg` keys to the package's own file, a stored `sender=None`-style option is never listed as a receiver, and a provider value is paired only within one object literal. On "which receivers run when request_finished is sent" (Django) the answer now names `close_caches`, `reset_urlconf` and `close_old_connections` with their sites and the send sites (+0.7 KB); on "which event plugin handles (keydown.enter)" (Angular) it names the `DomEventsPlugin` and `KeyEventsPlugin` providers in browser.ts (+0.7 KB). Python files are re-parsed once (parser version bump). `RIPWIRE_NO_REG_ROWS=1` turns it off. A row is printed only when every registration is provably the key's: an aliased import is looked up under the written name, a function-local import / lambda parameter / comprehension target / module-level `for` or `with` target named like the key is not the key, a provider value pairs only with the `provide` of its own object (a callee called twice from one symbol pairs nothing), and a registrar that also stores another required parameter beside a wrapped receiver is not a registrar.
