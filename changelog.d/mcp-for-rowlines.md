### Changed — MCP `for` serves its `<sigs>` and `<tail>` rows as text lines too, with a `rows` argument to opt out

The CLI `--for`'s row form (rows as lines in one CDATA per section, sequential ranks unspelled) now applies to the MCP `for` bundle: the same two legend clauses, the same line grammar, the same decoder (`test/rowlines.py`). A new `rows` argument mirrors `--rows=`: `"lines"` (the default) or `"elements"`, and it decides over `RIPWIRE_NO_ROWLINES=1` in both directions; any other value, or an empty one, is refused. The file page (`limit=` / `offset=`) is unchanged, as the CLI's is. A batch `for` sub-query takes the default form (the variable still turns it off).

It is lossless: decoded, the answer is the `rows:"elements"` answer byte for byte, and `rows:"elements"` is the previous release's MCP `for` answer byte for byte (`test/mcpforrowscheck.sh`). The bundle keeps its `demote:` note inside `<sigs>`, so the note rides the CDATA as a verbatim line (a line starting with `<`). Under the default session legend (`--mcp-legend=session`) a later answer still drops exactly what it drops from the element form — the row clauses and the note once served — and sends no definition twice, so each call of a session decodes to the element session's call byte for byte. `est_tokens=` stays the element form's price, an upper bound, as on the CLI. The `tools/list` manifest grows 73 B (the one property).
