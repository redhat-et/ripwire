### Changed — a `--for` tail row no longer repeats the names its file's ranked rows already show

A `<tail>` page row for a file whose symbols the answer already prints as ranked `<d>` rows used to list those same names again in `sym=`, so the row named nothing new. Its `sym=` now skips the names a shown row of that file carries and fills its three slots from the file's next positive-score symbols in the same lens order. The row count stays the same, and `sym=` never holds more names than before. A file whose positive-score names are all shown prints `p=` only. On the 321 in-sample `--for` calls this names the missing in-file symbol on mf2-pydantic-08 and nfpm-11, with no graded item lost on the near-match grade, and the changed answers are 0.2 % smaller on average (largest growth +0.8 %). Both tail legend clauses say it: sym= is the file's top symbols minus names a sigs row shows. The `<syms>` lead block skips a name the answer already prints, so a lead whose name the tail now carries gives way to the next candidate. `test/deeptailcheck.sh` arm (1d) pins the refill and its positive twin.
