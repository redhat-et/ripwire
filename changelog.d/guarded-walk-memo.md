### Fixed — a C++ map no longer re-walks the same base classes on every call: llvm-project's cold map left a 10+ minute single-core loop

The C-family base walk that decides which base class a call reaches (the guard that tells same-named base classes apart) expanded the receiver type's base levels again on every call. One level's expansion pairs every class of the deriving name with every class of the base name, so where class names repeat across files — `Impl`, `Base`, `Visitor`, hundreds of each in llvm-project — the cost was calls × (classes of a name)², and a cold flagless map of llvm-project sat in that loop on one core for more than ten minutes. The levels depend only on the root type's name, so each root's levels are now kept as they are first expanded and replayed by every later call; no level is expanded twice. The probe after each level had the same shape: for a member defined out of line in a file with no class of its name, it re-read every class of that name on every call. That answer — which classes of a name a file most plausibly means — depends only on the file and the name; it is now kept per (file, name) and shared by every walk that asks it (the ancestor and subclass walks of class identity asked it too, again per method). Class identity's step for a virtual call on a type that declares the method but defines it nowhere (the definitions in its real subclasses) likewise re-read, for every method, whether each subclass's base clause means the receiver class and the base levels a subclass inherits its body through; both are now kept per class. Telling same-named base classes apart paired every class of the deriving name with every class of the base name; it now walks whichever side is shorter — a class's own base edges, or the classes of the name. The reading of one base name by one deriving name is now computed once and shared by every walk that meets it, and the inherited-body walk's visited test is a set rather than a scan of a list that held every namesake reached. And the base closure the ladder's proof and the bare-call test read for a caller's class was kept for one class at a time, so every switch between caller classes re-expanded it; each class's closure is now kept. Every answer is unchanged byte for byte. `RIPWIRE_STATS` prints the counts as `[mem] guarded_walk`, `[mem] plausible`, `[mem] base_edges` and `[mem] subclass_walk`, and `test/guardedwalkcheck.sh` holds the walk to one expansion per root name and the probe to one read per out-of-line definition.
