### Fixed — a C++ map no longer re-walks the same base classes on every call: llvm-project's cold map left a 10+ minute single-core loop

The C-family base walk that decides which base class a call reaches (the guard that tells same-named base classes apart) expanded the receiver type's base levels again on every call. One level's expansion pairs every class of the deriving name with every class of the base name, so where class names repeat across files — `Impl`, `Base`, `Visitor`, hundreds of each in llvm-project — the cost was calls × (classes of a name)², and a cold flagless map of llvm-project sat in that loop on one core for more than ten minutes. The levels depend only on the root type's name, so each root's levels are now kept as they are first expanded and replayed by every later call; no level is expanded twice. Every answer is unchanged byte for byte. `RIPWIRE_STATS` prints the walk's counts as `[mem] guarded_walk`, and `test/guardedwalkcheck.sh` holds the walk's cost to one expansion per root name.
