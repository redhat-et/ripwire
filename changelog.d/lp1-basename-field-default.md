### Changed — `--for` scores a symbol's file basename as a ranking field by default

A question often names a file, a module or a package rather than a function ("lib/theme.githelpers: remove dead code", "restorer: reject trees …"), and a function's own text rarely repeats its file's name. The basename-only BM25 field has existed since the LB-3 round behind `RIPWIRE_BASENAME_W` and shipped at 0. The code lens (`--for`, `--pack-task`, and the MCP `for` and `pack_task` verbs, which share one constant) now scores it at weight 2: under a symbol's name (3), over its body (1). `--query`, `--recall` and the evals are unchanged.

Found by mining the GA1 DEV questions two peer tools answer and ripwire did not: codebase-memory-mcp indexes each node's file path and qualified name at the same BM25 weight as its name, and graphify starts its traversal from the file node a query word names. Measured on GA1 DEV (89 questions, page 1, the shipped argv): every-file-and-every-function complete 66 → 67 (ga-bash-it-01, missed → complete), function rung 62 → 64, body rung 24 → 27, no question down at any rung; median answer +15 B. The full-path field at weight 1 took two questions down on the same set, so it stays off. GA1 DEV is the set the change was found on; the held-out acceptance (a fresh question set and LocBench) has not run yet. `RIPWIRE_BASENAME_W=0` restores the previous ranking. `test/forbasenamedefaultcheck.sh` pins it for JavaScript and Go, CLI and MCP.
