### Changed — a `--for` task with no table or registration word still reaches a registration row

The table block that ends a `--for` answer (`<lit shape="table">`) used to need a word such as register, table, default or handler in the task. A bare subject (`new_boxed_executor for HashJoinNode`, `light.turn_on hue async_turn_on`) has none, so the block never ran. Now such a task runs the same walk over its backticked spans and identifier-shaped words, but lists only strong rows: an argument of a registration call (`reg=`), a top-level macro or call row (`tbl="item"`), or a row of a macro table (`for_all_params! {`, `$macro! {`). A registration counts only when the site is a direct argument of the call (`register(handler)`; not `register(wrap(handler))`, `register(table[handler])` or a site inside an object literal). A dict, list, `__all__`, `#define` or const-array row, and a site that is no row, is weak: counted in `weak=N`, never listed; with no strong row the answer is unchanged. A task with no identifier-shaped word and no backticked span scans nothing, and neither does a no-cue anchor that is one plain lower-case word (`register`, `open`, `index`: no `_`, `::`, `.`, digit or capital; a backticked span is still scanned), and a walk that lists no strong row adds no `<lit_capped>` note either. The legend clause that says this rides only on such an answer.

The callee names that count as a registration are narrower: `use` is no adding verb (it is the prefix of hooks such as `useRouter`), the noun after an adding verb must be the name's last word (`addEventHandler` is one, `addCommandLineOption` is not), and `reg` is a verb only as the last word or right before route, command or handler (`async_reg`, `reg_handler`; not `reg_value` or `reg_field`, a hardware register). The table legend is shorter: it no longer lists the vocabulary or the ranking of generated files, says the registration call is looked for 4 lines and 512 bytes above the site, and the `tail=` sentence rides only beside a `tail=`.

Gate `forregrowcheck` (N23, N24 for the last two rules) covers bare subjects on Rust, Python, Go and TypeScript fixtures, a weak row beside a strong one, weak-only rows of four kinds (each answer byte-identical with the block switched off), the no-call shapes, and the vocabulary cases above with their twins.

What it does NOT do: it does not list a weak row for a task with no cue word, even when that row is the answer; ask with a table or registration word for those. A callee's name is still no proof the call registers.

### Changed — a `--for` excerpt shows the match arm or case that holds the literal; `body="above"` only when the body was printed

An `<x>` excerpt in the `<lit>` block shows one window around each site, from the line before it. When that window leaves out the head of the match arm or case holding the site, the window now starts at that head, at most 12 lines up, and the excerpt says `arm="1"` (a legend clause rides only with it). Arms are an allowlist: a Rust, C# or PHP `Pattern => {` with balanced parens (never a JavaScript `x => {` callback), a `case` or `default` label (C, C++, Java, JavaScript, TypeScript, Go, C#, Swift, Python `match`; a `default: {` key of a JavaScript object literal, which heads no `switch`, is not one), a Python `elif` or `else:`, a Ruby `when`, `elsif` or `else`, and an `else if` or `else` branch in C-family and Go code. Openers the window already shows (an `else {` right above the site) are passed over to the arm above them; an `if`, a loop or a function above the window ends the walk with the old window. Measured on risingwave-02 (all three wordings): the window of `handle_alter_streaming_rate_limit` now starts at the `(Table, Source) =>` arm and holds the field read that picks the throttled id.

A `<ls>` row said `body="above"` when its owner's line, path and name appeared anywhere after the ranked rows, including a hop row (`<h>`) whose body the fold skipped. It now says so only when the answer printed the owner's whole `<b>`; a hop row, a fold skip or a truncated `<b>` that stops before the site is no body above, and the block serves its own excerpt. Gate `forliteralcheck` E1-E12 and B1-B3.

### Added — a `--for` task that names a `--flag` reaches the call that defines it and the default it takes

A task naming a flag (`kubelet --max-pods`, `How does the kubelet use the --max-pods flag?`; a `--` token whose name holds a hyphen, or a `--` name of 5 bytes or more right before the word flag or option) now gets a `<lit shape="flag">` when no earlier literal of the task has a source site. Its rows are the sites where the name is a whole quoted string (`"max-pods"`, `"--workers"`; its definition is one of them, an invocation or a lookup another); a name with no inner hyphen (`--compress`) is a site only in its dashed form (`'--compress'`) or as an argument of a flag-definition call (`fs.Bool("verbose", ...)` or a TCLAP `ValueArg<T> name(...)`), never a dict value, an `__all__` entry or an error message. Any other source hit (usage text, a longer flag such as `max-pods-per-core`) is counted in `mention=`. On the first such row that has one, `def=` is the default of a flag-definition call, read from the text: a `default=`, `default_value=` or boost `default_value(10)` argument, else the default slot of a Go flag, pflag or cobra call (the argument after the name, two after it for the `P` form such as `StringVarP`), never a usage sentence. A call that is no such flag call (an `exec.Command("tool", "--output-format", "yaml")` invocation, a nushell `.named("end-date", SyntaxShape::String, ...)`, an argparse alias `"-v"`) has no `def=`. When `def=` names a field (`c.MaxPods`), `<ld>` rows list the constant writes of that field (`obj.MaxPods = 110`, `MaxPods: 110`, never a copy `out.MaxPods = in.MaxPods`) in code that names the type of the receiver in `def=` (its parameter type, a package variable's declared type or its own name; a name match, no type check; a receiver with no type found lists none), functions and files named for defaults first, at most 2, with `writes=` counting all of them. Measured on kubernetes-05 (stored and both natural wordings): the `max-pods` registration row prints with `def="c.MaxPods"`, and the first `<ld>` row is the 110 default in `SetDefaults_KubeletConfiguration`. Gate `forliteralcheck` F1-F28 covers Go pflag (plain and shorthand), Python argparse and click, a flag with no default, a default that is a call, a C++ TCLAP argument, an alias after the name, a nushell `.named`, an invocation ranked before the registration, a no-hyphen name met as a dict value, a same-named field of another struct, and near misses (docs only, no site, a Rust clap field, no flag word, no flag).

What it does NOT do: it does not read a flag that has no quoted name (a Rust clap field, gflags `DEFINE_int32(name, ...)`), it does not follow a default through a variable or a call, and `def=` is the text of the argument, not the value in effect.
