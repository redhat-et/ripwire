### Fixed — C/C++ call edges read the include roots, and a call qualified by a namespace the tree never defines stays hedged (#478, thanks @jflowers)

The C-ROOT-INCLUDE change (#524) gave C/C++ trees their include-root file edges but kept the call narrow on the includer-directory closure, because coupling them bound about 300 Envoy calls to a wrong in-tree namesake without a hedge. The call narrow's include-file rule (Rule 3) now reads the root edges, behind two vetoes. First, a C/C++ call qualified by a name the tree never defines (no class, struct, alias or namespace of that name in any definition's scope or member path) takes no include proof: `absl::Span(…)` no longer binds Envoy's own `class Span`, and `fmt::ptr(…)` no longer binds `OptRef::ptr`. The pick keeps the existing `via="name"` hedge. Second, a `std::f(…)` call must name a member of namespace std itself, so `std::format(…)` never binds the `format` member of a `std::formatter<…>` specialization. Member calls on a typed receiver keep the includer-directory closure, so they gain nothing from the root edges.

Measured on Envoy (site dumps, hand read; the method is the one #478's Ca/Ce measure motivated): 2,819 call sites gain an unhedged bind against the decoupled build, and a hand sample of 30 of them is 29 right. Without the vetoes the same coupling was 18 / 30, and all 156 calls qualified by `absl`, `fmt`, `nostd`, `grpc`, `testing` and the like were wrong; the vetoes remove all 156. On htop, 13 sites gain (`Machine_new → Machine_init` on nine platforms through the root `Machine.h`), all right; ninja is unchanged. On ClickHouse, 122 sites gain (about 121 right), and 183 wrong binds drop: `std::find(…)` and `std::string_view(…)` had bound a polyfill `namespace std { struct string_view }` that only one file includes. Answers: of 61 graded C/C++ questions (Envoy, htop, tmux, ninja), 48 are byte-identical and 10 change only counts or rank order. In 3 Envoy answers a ranked row gives way to a newly connected one. One of those is an error-task callers block that no longer prints, because the function it names now has five callers, four of them `via="name"` hedges.

What it does NOT fix: a qualifier the tree does define but that aliases an external namespace (Envoy's `namespace Protobuf = google::protobuf`, so `Protobuf::Map` binds an in-tree `Map`): about 37 Envoy sites, because C++ namespace aliases are not recorded yet. It also does not fix the right typed-receiver binds the second veto gives up (about 44 on Envoy).
