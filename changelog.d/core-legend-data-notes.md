### Fixed — the default `--for` page 1 keeps its data notes: `--adaptive`'s cut, the doc-mention surfacing and the relevance floor are disclosed again

θ5 (0.7.0) gave the defaulted CLI `--for` page 1 a *core* legend: the first (schema) comment of the document legend, cut at a `"; "` clause boundary to fit 1 KiB including a pointer to the full legend (`--legend=last`), with the freed bytes handed to rows. The cut is a cut of **definitions**, and a definition survives it because the pointer names the call that prints the same bytes in every answer.

The note channels are not definitions. `" [adaptive: kept 7 of 40 - cliff at rank 7, 61% drop]"`, `" [doc mentions: 2 docs, 1 symbol; doc_mentions=]"` and `" [floor: kept 7 of 40]"` are **this answer's data** — the cliff rank, the drop, what the surfacing found. They are appended last, so they sat in the comment's final bytes and were the first thing the 1 KiB cut threw away. This repo's own `--for="tree-sitter parse of a source file" --adaptive` carried a 1,661 B schema comment whose last 220 B were exactly those two notes: the defaulted posture disclosed no narrowing at all, while `--legend=compact`, `=full`, `=last` and `RIPWIRE_NO_CORE_LEGEND=1` each carried it. Following the pointer does not recover a datum the way it recovers a definition — it re-runs the query and re-derives it.

It also silently undid `SHOWCASE-TAIL-SEAM` (2026-11-20), a fix made so that very `[adaptive: kept N of N]` clause would reach the page. `showcasecapturecheck` arm (G) is what caught it, four days later, as a caption claiming a clause its block no longer held.

The notes are now held back from the clause cut and appended after the pointer, **charged to the same 1 KiB**: they displace definition clauses rather than widening the core, so page-1 bytes are unchanged and `corelegendcheck` (C1)'s bounds are untouched. On this repo the `--adaptive` schema comment is 1,002 B with both notes and the pointer. A group counts as a note only if it is `" ["` … `"]"` holding no further `]` and carrying a `": "` label seam — the shape every emitter writes; prose that merely ends in a bracket stays in the cuttable body.

Gate: `corelegendcheck` arm **(C10)** — every note the full `--legend=last` page 1 carries is in the core schema comment too, on the default fixture (one note) and on an `--adaptive` fixture (two notes back to back, so the multi-note walk is exercised), and that comment still meets (C1)'s bounds. It counts the notes it read and fails on zero, so it cannot pass vacuously. **(C10n)** is the negative control: the same comparison against a core page with its note tail stripped must fail. Both arms are red on a pre-fix binary and green after, with no other arm moving.
