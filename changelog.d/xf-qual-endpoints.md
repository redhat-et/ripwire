### Fixed — a qualified `--connect` terminal and `--edit-check` selector answer about the definition they name

`--connect=ProcessList::insert,InterpreterFactory::get` already searched only the two qualified definitions, but each terminal row printed the bare name's definition count (`defs="196"`, `defs="645"`) under a legend saying all of them were searched, which read as the qualifier being dropped. A terminal spelled with an owner, module or file (`A::m`, `Class.method`, `ns.fn`, `pkg.mod.fn`, `file:name`) now reports the definitions its spelling searched (omitted when one). On TS/JS, which store no owner scope, `--edit-check=Alpha.run` (and the MCP `edit_check`) unioned a same-file `Beta.run`, and `ns.make` a sibling namespace's `make`, so the contract listed the other definition's callers; a selector that names an owner now keeps only the definitions it resolves to. Bare names answer byte-identically. New gate `test/qualendpointcheck.sh` pins every endpoint verb's resolution of these spellings in C++, Python and TS, and the refusal of an unknown qualifier.
