### Fixed — a `found="0"` answer of `--callers` / `--uses` / `--impact` names the plain-text occurrences of the name

When no indexed definition matches the selector, the three "who uses it" verbs (and their MCP twins, in the refusal's `error.data.answer`) still answer `found="0"` with exit status 1, and, when the selector is a bare name, now also carry it as a whole word in the indexed files: `text_hits=` (lines), `text_files=`, one `<text p="FILE:LINE" n="N"/>` row per file (its first such line and its line count; at most 20 rows, source files first) and `next="--grep=NAME"`. The legend labels them PLAIN TEXT, never a call or a use the graph proved. fastify keys a reply property with `kReplyHijacked: Symbol( … )`, an object-literal key and not a definition, so every graph verb answered an empty `found="0"` while the files that read and write `reply[kReplyHijacked]` were one `--grep` away. The scan is the literal `--grep` scan plus a whole-word test, bounded (512 files, 64 MB read; a stop prints `counts_floor="1"`). A qualified selector (an unknown qualifier stays refused, never read as the bare name), a name no file holds, a refusal over several definitions, `--callees`, `--defs` and `--path` answer exactly as before.
