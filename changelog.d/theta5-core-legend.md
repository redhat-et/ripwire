### Changed — the default `--for` page 1 carries a core legend and more rows

Page 1 of a default (CLI, no `--legend=`) `--for` answer used to end with the whole document legend, about 3 KB and 29 % of the page. It now keeps the core: the first (schema) comment, cut at a `; ` clause boundary to at most 1 KiB, ending in a pointer to the full legend (`--legend=last`, the same answer-first pages with today's legend). The bytes this frees go to the next rows in page order, so page 1 holds more rows and is never larger than the full-legend page 1. The row-line clauses stay. A one-page default answer carries the core legend too. `--legend=last`, any spelled posture, `--page-bytes=0`, the MCP server and `RIPWIRE_NO_CORE_LEGEND=1` keep the whole legend. This is the loop's θ5 (PLAN_071 §1.5). Offline on the in-sample sets it moved complete/partial/wrong from 165/86/7 to 168/83/7, with page-1 bytes down and no located item lost. New gate `test/corelegendcheck.sh`; gates that pin the in-page definition contract run with `RIPWIRE_NO_CORE_LEGEND=1`.
