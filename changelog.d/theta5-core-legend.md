### Changed — the default `--for` page 1 carries a core legend and more rows

Page 1 of a default (CLI, no `--legend=`) `--for` answer used to end with the whole document legend, about 3 KB and 29 % of the page. It now keeps the core: the first (schema) comment, cut at a `; ` clause boundary to at most 1 KiB, ending in a pointer to the full legend (`--legend=last`, the same answer-first pages with today's legend), plus one short comment that defines every paging and act attribute the page carries (`page=` `pages=` `withheld_bytes=` `continued=` `deferred=` `next=` `root=` `at=`, the act line's `read=`, and demote). The bytes this frees go to the next `<tail>` rows, so page 1 holds more rows and is never larger than the full-legend page 1. The row-line clauses stay. A one-page default answer carries the core legend too. `--legend=last` and `--legend=compact` (the same pages with the whole legend), `--legend=full` (the long prose form), `--legend=first` (legend first, unpaged), `--page-bytes=0`, the MCP server and `RIPWIRE_NO_CORE_LEGEND=1` keep the whole legend. A spelled posture is named in every page's `next=` as typed (`--legend=last` pages on with `--legend=last`), so each page is cut under the legend page 1 was cut under; the default `next=` is unchanged. `--legend=dict` carries no core either, but it is its own posture: where it applies it replaces the prose legend with a pointer to `--legend-dict`; a `--for` answer is not reduced by it, so `--for --legend=dict` is served byte-identical to `--legend=compact`. This is the loop's θ5 (PLAN_071 §1.5). Offline on the in-sample sets it moved complete/partial/wrong from 165/86/7 to 168/83/7, with page-1 bytes down and no located item lost. New gate `test/corelegendcheck.sh`; gates that pin the in-page definition contract run with `RIPWIRE_NO_CORE_LEGEND=1`.
