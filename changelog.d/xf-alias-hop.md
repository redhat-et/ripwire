### Added — an alias leads to what it names: `--for` follows the chain, `--uses` lists the sites written through it

`--for=ColumnPtr` printed `using ColumnPtr = COW<IColumn>::Ptr` and stopped there: what the alias stands for (`COW::Ptr`, then `using Ptr = immutable_ptr<Derived>`, then the class `immutable_ptr`) and the class it points at (`IColumn`) each took another call. A `--for` answer now ends with an `<aliases>` block when the name the task spells (the route's name, or a sentence's one code-shaped name) has an alias definition: one `<chain>` per distinct walk, one `<h via="alias">` row per definition reached with its declaration text and `d=` hops, the template argument of the first target as `arg="1"` (the pointee of a smart-pointer alias) with its member count and first names, and a `<leaf>` for a spelling no definition in the tree binds (`std::shared_ptr`, a template parameter's member). The walk is bounded (4 hops, 3 definitions per spelling, 3 chains, `cycle="1"` / `depth_capped="1"` / `capped="1"` when they cut), sits outside `est_tokens`, and under a token budget prints a one-line held marker. Under `--max-tokens` it leaves out the member names (`m=`) and the chains that reach only leaves, and says so with `shed=`. Its legend explains only the attributes the block prints. A written qualifier is checked against the namespaces and classes around each definition, read from the file's braces (a C++ class's own scope is just its name): `using WQ = N2::Widget` binds the class in `N2` and never a namesake in `N1`. A leading `::` (`using W = ::Widget`) binds the global definition, and a space beside `::` (`N :: Widget`) is still one name. When a bind cannot be proven (the braces do not balance, at the target or at the alias itself), the row says `bound="name"` instead of claiming the target is not in the tree. A string literal in the target (`Tok<"…">`) is no name, and the declaration text, `to=` and leaves are redacted like every other printed source line (`--no-redact` passes them through). `--defs to=` is redacted the same way. A type's `members=` counts its own member functions only. The block is printed by the CLI in XML only: the MCP `for` tool, `--json` and `--format=columnar` carry none (`--help` says so). `RIPWIRE_NO_ALIAS_HOP` turns it off.

`--uses=IColumn` now also lists the sites written as an alias whose chain reaches `IColumn` (`ColumnPtr`, an alias of that alias, `std::shared_ptr<IColumn>`), each marked `via="alias" alias="ColumnPtr"`, after the direct rows. A site counts in `count=` and `via_alias=` only when the alias in scope there (the innermost one of that name visible from the site) is one that reaches `IColumn`; other sites written with the same name are listed last with `hedge="name"`, counted in `alias_hedged=` and not in `count=`. `alias_namesakes=` says how many other definitions share an alias's name, and `alias_depth_capped="1"` says the reverse walk stopped at 4 hops with an alias still to follow (one hop per round, whatever the declaration order). An alias declared later in the same file is not the one in scope at an earlier site, and a site whose braces cannot be read is hedged when the alias name has namesakes. A `file:Name` or `Scope::Name` selector lists the alias sites of the definitions it chose. The columnar form counts them as `alias_sites_held=` instead of listing them. A definition inside another translation unit's source file (an example program's own `class IColumn`) is not what a header alias names while another definition of the name remains.

C++ only for now (headers included): its alias definitions are the ones that record a target. A TypeScript or Rust `type X = Y`, a Rust `use … as`, and a Python module alias get no block yet. The MCP and LSP `uses` answers list no alias sites. Gate: `test/xfaliashopcheck.sh`.
