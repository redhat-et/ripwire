### Fixed — `--for` reads `confidence="high"` on a name-exact route only when the anchor heads the rows

- `--for` and the MCP `for` verb: `confidence=` measures how far the scores drop below the ranked head, so on a name-exact route it vouches for the anchor only when the head row is the anchor (a symbol of the anchor's name, or a row in the file the anchor is defined in or a file subject names). When another symbol heads the rows, as a plain word's namesake does in `where concurrent.futures.ThreadPoolExecutor is defined`, confidence reads low and `route=` appends `; anchor is not the ranked head (r=1 is NAME in PATH)`. The rows themselves do not move. A conceptual route has no anchor and reads as before. "The ranked head" is the row the answer prints as r=1: code above docs moves Markdown rows below the code rows, so a Markdown heading that scored first does not make the anchor look unproven when the anchor prints first. A word that spells a symbol the index holds (`FooBar.py` as the method `py` of `FooBar`) is not read as a file subject because a file of that spelling exists. The review of #568 found both (thanks CodeRabbit); `test/subjectanchorcheck.sh` arms FH(d) to FH(f) cover them, CLI and MCP.
