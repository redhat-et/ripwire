### Changed — `--recall` serves the best-matching part of an HTML page it has to cut, not its start

A recalled document with no headings to cut by (an HTML page's text, a heading-less note) that does not fit its share of the budget used to keep its first bytes: on an HTML page, that is the navigation list and the table of contents. It now keeps the run of whole lines, of the same size, that carries the most query evidence (each line scores the query words it holds, rarer words in this document weighing more; the earliest of equal runs wins, and a document whose start scores best, or ties the best, still serves its start: the run must out-score the whole lines of the head cut as it would be served). The separator line says so: `[truncated: K of N bytes; served bytes LO-HI, best query-term window]`, where LO-HI is the byte range of the served text (the converted text for an HTML page), and the body opens with a `…` line; on an HTML page the page's title (its first line) sits above that line, so a window from deep in a long page still names its page (the title is not part of LO-HI). A window that reaches the end of the page keeps the page's last line. A window that starts inside a code fence repeats the fence's opening line (`fence_reopened`); one that ends inside a fence or table keeps its own last line and closes the fence (`fence_closed`), rather than dropping back behind the line it was chosen for; the repeated opening line is charged to the window before its lines are scored, so the lines scored are the lines served; an opening line over 64 bytes is repeated as its bare fence run plus the first word of its info string (or not at all when the run alone is over 64 bytes), and a table whose rows start with a backtick is not a fence.

Measured on the same 48-question docs set as the 6-doc recall default change: development questions fully answered went from 13 to 16 and held-out from 4 to 5, all on HTML pages (8 development and 4 held-out HTML questions; Markdown and reStructuredText answers are byte-identical). Mean answer size on the development set rose 0.7 %, from the marker, the `…` line and the title line.
