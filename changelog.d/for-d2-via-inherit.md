### Fixed — a `--for` second-hop caller reached only through a by-name caller is hedged `via="name"`

The `<callers>` element of a `--for` answer hedged a `d="2"` row only when that row's own call into a first-hop caller was matched by name. A row whose call was resolved but whose first-hop caller was itself matched by name alone (`via="name"`) printed unhedged, though nothing proves it reaches the function: on nushell, `--for="what calls PolarsPluginObject::into_value"` printed `CustomValueSupport::to_pipeline_data d="2"` with no hedge under three by-name first-hop rows. A `d="2"` row now carries `via="name"` unless at least one resolved call joins it to a first-hop row that is not matched by name alone, including a first-hop row the 16-row cap hides; a row with one such path stays unhedged. The six caller-hop legend clauses (named, ranked and subject routes, full and compact) say so: `via=name if every path has a by-name hop`. Only `--for` answers that carry a `<callers>` element change: that element's legend clause and the `via=` attribute of the second-hop rows this rule hedges. `test/forcallerhopcheck.sh` gains arm V1 on Rust, Python, TypeScript and C++ fixtures: a row reached only through a by-name caller, a row with one proven and one by-name path, a row whose own call is by name, a row whose only proven call goes into the by-name caller (Python), and a row whose only proven path runs through a first-hop caller the cap hides (Python).
