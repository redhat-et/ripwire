### Added — a `--for` task about a table or a registration reaches the sites of the identifier it names

When no other literal of the task has a source site, `<lit>` makes a last try, `shape="table"`. It needs one of these in the task's own words, outside backticks: a registration word (`register`, `registered`, `registry`, `registrar` and their forms), `table`, `compile-time` or `compile time`, `add a new` or `implement another`; or `default` or `handler`, which print only when a site reads as a table row. Its anchors are the task's backticked spans, then identifier-shaped words, then a plain word after `like`, `alongside` or `following`: at most 3, and any word that is not backticked must be the name of a symbol in the index. A hit stands on word edges; a hit inside a longer word is counted in `longer=`.

Each anchor with a source site prints its own `<lit>`, the legend on the first only. A site that reads as a table row ranks first: a map or dict key, a list member, a `{ name, ...` row or a call beside a sibling of the same shape at its indent, or a macro or ALLCAPS call outside any function (a Go map entry, a Rust macro row, a C X-macro line). Such a row carries `tbl=`, the line that opens the table (`item` at top level), and the first four carry `lines=a-b`, the lines after them. This is a reading of the line's text, not of the parse: a struct literal in a function can read as a table row too, and a row is never dropped for not being one. Rows stop at 32 per anchor and all the elements of a task at 40,000 bytes, cut on a row boundary with `capped="1"` and `next=`; an anchor the cap left out is counted by `<lit_capped>`. Everything before the element stays byte-identical. Gate: `test/forliteralcheck.sh`.
