### Fixed — `--for` on a "path from A to B" question ranks on A and B, and a missing path shows both sides

A `--for` task worded as a two-endpoint graph question ranked its frame words as subject words: "what is the path from parseConfigFileWithSystem to createProgram?" declined on `path` (hundreds of definitions) and its ranked rows drifted to path-handling code. Tasks of four closed shapes (`[what is the | trace the] [call] path from A to B`, `[call] chain from A to B`, `how does A reach B` / `get to` / `lead to`, `[lowest] common caller of A and B`) now rank on the two endpoints' words only, and `route=` names the dropped frame words (`dropped: path`). The word `path` anywhere else ("where is the config path parsed", "strip the directory path from ...") is not the form. When the path verb the task already runs finds no directed path (`reachable="0"`), a new `<path_gap from= to=>` block inside the graph block carries the endpoint's callees and the other endpoint's callers, each the plain `--callees` / `--callers` answer with its own legend, and says a name common to both sides is a candidate link, not a proven path. A found path prints exactly what it printed before. The MCP `for` verb gets the ranking change, not the gap block. New gate `test/graphformendpointscheck.sh`.
