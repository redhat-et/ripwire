### Changed — the warm snapshot is recorded by the run that parses (RECORD-FIRST, #729)

The warm snapshot (`ripwire-warmsnap-…bin`) used to be written only by a run that re-extracted nothing, so after every edit, and after the first run on a tree, two calls parsed before a third was served from the snapshot. Since snapshot format 10 a run that parsed records the snapshot too, so the next call is served. The file has a header with a table of three sections (TREE, MODEL, GRAPH) at 16 KiB boundaries; each section has its own digest and is checked only when a run reads it. The file is memory-mapped, and the writer streams the model and graph sections to disk as they are built instead of holding a second copy in memory. Inside the 2-second window after an edit, only the TREE section is held back, so the next call loads the graph and builds the model. `RIPWIRE_NO_RECORD_FIRST=1` restores the old rule. `test/recordfirstcheck.sh` checks that calls 1, 2 and 3 give the same answer for the map and `--for` in either order, with and without the snapshot, and that each invalidation reports its `why=`.
