### Changed — warm `--deps` on a large TypeScript tree uses about a fifth less CPU

Resolving one relative TS/JS import (`./util`) tried up to 16 file names (`util.ts`, `util.tsx`, …, `util/index.jsx`), and each try built and normalized a new path string. The directory and the specifier are now joined and normalized once per import and each try is a lookup; inside one include-graph build, an import that repeats a (directory, specifier) pair takes the first answer, including a miss. On a single root, the shared join step behind the other languages' path probes also stops allocating per try; Rust, Python and Ruby still build their candidate strings, and a multi-root tree takes the previous path. Measured warm on one machine, median of three interleaved pairs against the previous build: vscode `--deps` user CPU -22 % and instructions retired -23 %. envoy (C/C++) and cockroach (Go) do little of this work: instructions -1 % and 0 %. Peak footprint (MiB) is unchanged in each of those runs.

Answers are unchanged where it was checked: 9 warm and 3 cold base-versus-new output pairs on those three repos are byte-identical. A new case in `test/tsimportprecisecheck.sh` resolves one specifier from two directories to two files and keeps a miss a miss after another directory's hit.
