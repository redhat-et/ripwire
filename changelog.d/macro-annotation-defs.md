### Fixed — a trailing C/C++ annotation macro no longer takes over the function it annotates

`T f( a ) ABSL_EXCLUSIVE_LOCKS_REQUIRED( mu ) { body }` parses as a prototype `f` and a typeless definition named after the annotation, which owned `f`'s body and calls. `f` was left as a body-less declaration, or missing outright when its parentheses were empty (`void A::f() ABSL_…( mu ) {` reads `A::f()` as a variable), so its callees went to a phantom named `ABSL_EXCLUSIVE_LOCKS_REQUIRED` and its callers bound to a declaration. Now the annotation is a `role="macro"` use of the macro, and `f` keeps its own name and body: constructors, destructors, templates, `const` / `noexcept` / `override` mixes, nested annotations (`DISABLE_…( ABSL_UNLOCK_FUNCTION() )`) and data members (`int g_ ABSL_GUARDED_BY( mu_ );`) included. The rule is the syntax, not a list of names. On envoy 134 annotation definitions are gone and 7 functions that were missing (`AdminResponse::sendErrorLockHeld`, `SymbolTable::newSymbol` …) are indexed; no other definition changed on envoy, cpython, cockroach, tmux, ninja or htop. Four envoy sites whose parse is too damaged to read (a templated return type, a double annotation, two namespace-scope `ABSL_GUARDED_BY` maps) are unchanged.
