### Changed — a broad `--for` answer's file tail walks the file page's first 160 rows, not 40

A broad `--for` answer cuts its `<tail>` of lower-ranked files. The tail used to list its rank rows and then the first 40 rows of the file page; on the 15 stored R-ladder rows the wanted file sat past that cut, at file-page rank 57-177, in 6 of the 7 items the raised-limit page recovered. The tail now keeps its rank rows unchanged and walks the first 160 rows of the file page (`kForFileTailPageWalk`), in the page's own order. `sym=` rides the rank rows and the rows the old 40-row walk listed; a row past that cut is path-only, so the extra rows cost about a third of a full row. The cut stays disclosed (`shown=`, `total=`, `capped="1"`, and `next=` continues the page at offset 160), and the tail legend gains a clause that says so, present only when the page has more than 40 rows. An answer whose file page fits the first page is byte-identical to before, legend included.

Measured on the 15 stored R-ladder rows (12 `--for`, 3 map) against main: R items credited 2 to 6 of 35, the 4 gained arrive in the first answer instead of after a raised-limit call, none lost, and the 15 answers grow 12 % in bytes (10 answers grow by 1.6-6.7 KB; the 3 map answers and the 2 whose file page fits one page are byte-identical).
