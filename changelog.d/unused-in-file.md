### Added — `--for` answers "which public X in <file> are unused"

A `--for` subject with an unused cue (`unused functions in util/network.py`, `quoteString.h unused functions`, `which exports of src/path.ts are never called`) that names a file or directory now carries an `<unused_in_file>` table: one row per public def, with a verdict that says what was proven. `used` means a non-test caller elsewhere (or an in-file chain from one); `test-only` that every reference found is in a test; `file-only` that only the same file refers to it; `unused` that the name appears nowhere in the tree outside its definition, declarations and comments. Anything an index cannot follow reads `unknown`, with `why=` naming it: a word no edge explains, a string lookup, a built name, a re-export, a star barrel, dynamic dispatch, a decorator or attribute, a surface consumers outside the tree may use, a build file. `--dead-code` keeps its internal-linkage meaning; a `--dead-code=PATH` root now names the table on `next=`.
