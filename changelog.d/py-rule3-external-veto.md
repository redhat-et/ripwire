### Fixed — a Python call to a builtin or an imported third-party name no longer binds to a same-named def in an imported file

`dict(...)`, `bool(...)`, `type(...)` or `float(...)` with no local, import or same-file def of the name, and a call to a name imported from a stdlib or third-party module (`from rich.padding import Padding`), used to be narrowed by Rule 3 to a namesake in a file the caller imports before the external-name veto could refuse it: on CPython 1,383 call edges and on Textual 25 (14 `type(...)`, 11 rich imports) went to an unrelated def. The veto now decides first, so those calls carry no edge. A file with `from m import *` of an indexed module, a name imported from an indexed module, a same-file or nested def, and a parameter or local of that name all keep their edge. Left as before: member calls with an unknown receiver, calls through a local variable, and a call through a module that exists in the tree under a stdlib name (`os.stat`, `inspect.signature` with an in-tree `os.py` or `inspect.py`).
