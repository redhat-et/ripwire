### Fixed — the `mem=` legend names every key of the order it prints (#595, thanks @soarkit)

A compact `--for` owner row lists its member names in `mem=` ordered by question words, then the owner's own file before other files, then path, then line. Both legend clauses stopped short of that: the full one said "question words first, then line", the compact one named no tie-break at all. A reader deriving the order from the legend got a different list whenever a member in another file had an earlier line than one in the owner's file. The order is unchanged (same-file members first is the useful one); both clauses now name owner's file, path and line. The cost is the clause only: +25 B compact and +20 B full, on answers that carry `mem=`. @soarkit found the mismatch, wrote the root cause and the two-file Rust reproduction in #595; `test/formembernamescheck.sh` (O arms) runs that reproduction and checks that the printed order is the order derived from the clause's own keys.
