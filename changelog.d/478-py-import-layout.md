### Fixed — Python file edges: stdlib-named siblings, src layouts, and directories the crawl denylist removes (#478)

Reported by @jflowers, who built an `ast` ground truth of pip's whole import graph and named the causes.

Inside a package, an absolute `import logging` no longer binds a sibling `logging.py`, in the file graph or the call graph; Python 3 has no implicit relative import. A plain script directory keeps its sibling, because it is `sys.path[0]` when the script runs. An absolute import now also resolves under a `src` directory beside the importer or any ancestor, and under the source root of the importer's own package chain (`lib/mypkg/a.py` importing `mypkg.b`). Those layout roots are a fallback: the repo root and a plain script directory are probed first and win over a namesake under `src`, and two layout roots that name one module degrade to no edge, as before. A `src` that holds an `__init__.py`, or sits inside a package, is a package and not a source root. A stdlib-named first segment (`logging`, `json`, from the CPython 3.13 `sys.stdlib_module_names`) does not bind through a layout root, because a repo file there shadows the stdlib only when that directory comes first on the path; a root that holds the stdlib itself (CPython's `Lib/`) is exempt. A file outside those shapes importing a package under a root that is not `src` stays unresolved. In a multi-root run, the call graph keeps a root that happens to be labelled `src` from binding another root's importer. Over `ast` truth, exact directories Ca/Ce: textual 86/3 to 98/98, flake8 62/25 to 100/100, pydantic 97/97 to 100/100 with 52 false edges gone.

Limits. A script inside a package (`pkg/__init__.py` beside `pkg/tool.py`, run as `python pkg/tool.py`, with `import helper`) puts its own directory first on `sys.path`, but the import resolver cannot tell a script from a module, so it loses that true sibling edge (three in the corpus, over about 6,000 package files). A namespace package (no `__init__.py`) cannot be told from a script directory and keeps its sibling edge. The older suffix binding for a unique `tools/logging.py` in a plain directory is unchanged.

`--skipped` now rows every directory counted in `pruned_dirs=`: `why="pruned-package"` when a build-output name (`build`, `dist`, `out`, `target`, `captures`) holds its own `__init__.py`, else `why="pruned-dir"`. `--arch` and `--deps` carry `<pruned_packages>` naming the real packages, present only when one was pruned, up to 8 with `count=` and `next="--skipped"` for the rest.
