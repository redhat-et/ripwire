### Fixed — Python file edges: stdlib-named siblings, src layouts, and directories the crawl denylist removes (#478)

Reported by @jflowers, who built an `ast` ground truth of pip's whole import graph and named the causes.

Inside a package, an absolute `import logging` no longer binds a sibling `logging.py`, in the file graph or the call graph; Python 3 has no implicit relative import. (A stray `__init__.py` at the repo root makes the root itself a package and does not trigger this: its `a.py -> logging.py` edge stays.) A plain script directory keeps its sibling, because it is `sys.path[0]` when the script runs. An absolute import now also resolves under a `src` directory beside the importer or any ancestor, and under the source root of the importer's own package chain (`lib/mypkg/a.py` importing `mypkg.b`). Those layout roots are a fallback: the repo root and a plain script directory are probed first and win over a namesake under `src`, and two layout roots that name one module degrade to no edge (the base resolver had no layout roots, so this is the new rule). A `src` that holds an `__init__.py`, or sits inside a package, is a package and not a source root. A stdlib-named first segment (`logging`, `json`, from the CPython 3.13 `sys.stdlib_module_names`) does not bind through a layout root, because a repo file there shadows the stdlib only when that directory comes first on the path; a root that holds the stdlib itself (CPython's `Lib/`) is exempt. A package that imports ITSELF is decided at its own chain root first, with no stdlib guard and no repo-root namesake in the way: `src/email/sender.py` with `from email.templates import t` binds `src/email/templates.py`, and `src/foo/b.py` beside a root `foo/` binds `src/foo`. Any other importer of that name (`src/api/routes.py`, `tests/`) stays unresolved, because the run mode decides whether the stdlib or `src/` comes first on the path and the resolver cannot know it. `__main__` is guarded like a stdlib name. A file outside those shapes importing a package under a root that is not `src` stays unresolved. In a multi-root run, the call graph refuses every hit in a root other than the importer's own (the file graph always did), so a root that happens to be labelled `src` cannot bind another root's importer. The one base-true edge this also removes: with `mypkg` and `tests` as two roots, `import mypkg; mypkg.ff()` from `tests/` goes from 1 caller to 0, matching the file graph. Over `ast` truth, exact directories Ca/Ce: textual 86/3 to 98/98, flake8 62/25 to 100/100, pydantic 97/97 to 100/100 with 52 false edges gone.

Limits. A script inside a package (`pkg/__init__.py` beside `pkg/tool.py`, run as `python pkg/tool.py`, with `import helper`) puts its own directory first on `sys.path`, but the import resolver cannot tell a script from a module, so it loses that true sibling edge with no hedge in the answer: in one fixture `--callers=run` goes from 2 callers to 0, `--impact=run` from 3 reached files to 0, and the importer count from 2 to 0. The commonest form is a `src/__init__.py` with `python src/train.py` doing `from utils import x` (`--impact` importers 1 to 0; `--callers` hedged). The corpus counted three of these over about 6,000 package files, but the corpus is library-heavy, so application repos with training or CLI scripts inside a package will lose more. A namespace package (no `__init__.py`) cannot be told from a script directory and keeps its sibling edge. The older suffix binding is unchanged: a plain `src/logging.py` or a unique `tools/logging.py` still binds `import logging; logging.info()` as a firm call edge from `pkg/`, `tools/` and `tests/` callers (3 callers in one fixture) while `--arch` and `--deps` show no edge. A non-self importer of a stdlib-named package under `src/` (`src/api/routes.py` doing `from email.sender import send`) is dropped from the file graph, and the answer does not say so.

`--skipped` now rows every directory counted in `pruned_dirs=`: `why="pruned-package"` when a build-output name (`build`, `dist`, `out`, `target`, `captures`) holds its own `__init__.py`, else `why="pruned-dir"`. `--arch` and `--deps` carry `<pruned_packages>` naming the real packages, present only when one was pruned, up to 8 with `count=` and `next="--skipped"` for the rest.
