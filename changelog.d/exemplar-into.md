### Changed — `--for` on an add-a-new-X task points INTO the one holder when the family holds X instead of being X

When most members of the family carry X's plural in their name (`ServerSettingsImpl`, `MergeTreeSettingsImpl` for a setting; `CompilerOptions` for an option), a new X is not one more member: it is a row inside one of them. The block now names that holder (`into=`, `into_p=`): the one a word of X names (`query-level` picks nothing, so the one general holder without other words is taken, `into_by="bare"`), else the one a task word names (`a new option for the compiler` picks `CompilerOptions`, `into_by="word" into_word="compiler"`; a tie picks none). Its existing rows follow in `<rows by= n=>`: the largest X-macro list in its file (`list=`, `list_p=`, the row name read from the argument position with the most distinct identifiers), else its fields, else its TypeScript `name?: type` property lines; the touch list is built over those rows. The other holders are not printed (they are other scopes, the wrong place to copy from), and when no single holder is pointed at the block is withheld instead of printing them. On the ClickHouse query-level setting task this resolves to the `COMMON_SETTINGS` list in `src/Core/Settings.cpp` instead of the server and table scope settings classes; on the TypeScript compiler-option task to `CompilerOptions` with `commandLineParser.ts` as the place the options are listed. Touch rows no longer read `docs/`, `doc/` or `unittests/` trees. New gate arms i1-i5 in `test/forexemplarcheck.sh`.
