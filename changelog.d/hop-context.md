### Added — `--path` and `--connect` hops print the call site, the call and the callee's signature

A `--path` hop row and a `--connect` `<e>` row used to name only the two definitions an edge joins, so the next step was opening the caller to find the call and the callee to read its parameters. Each hop now also prints `site="file:line"` (a call in the caller that names the callee; `sites="N"` when the caller has more than one such line), `call="…"` (that call's text from its line start, whitespace collapsed, joined across up to 3 lines while its parentheses are open, at most 120 bytes) and `sig="…"` (the callee's declaration signature, at most 160 bytes). The site is a name match, not proof that this call is the one the edge binds, and the legend says so. On `--path` the first reaching pair prints all three and later pairs print the site only; on `--connect` a callee's signature prints once per group and not where its join row already shows it. A call or signature whose file cannot be read, or changed since indexing, is left out and counted (`hop_unread=`); a site whose text does not name the callee is counted too (`hop_notext=`); an edge with no call naming the callee in its caller prints no site (`hop_nosite=`). Under `--max-tokens`, `--connect` drops these attributes first (`sig=`, then `call=`, then `site=`, named by `hop_shed=`) and only then trims as before. Two `<e>` rows that would read alike (two same-named targets reached from one caller) now print `tp=`/`fp=`, the definitions they join. The MCP `path_between` and `connect` tools print the same rows. `RIPWIRE_NO_HOP_CONTEXT=1` turns the attributes off. New gate `test/hopcontextcheck.sh` covers C, C++, Python, TypeScript, Go and Rust hops, unreadable and edited files, the shed order, and one reference pass for a 40-hop path.
