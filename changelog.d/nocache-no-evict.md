### Fixed — `--no-cache` no longer evicts other roots' cache blobs

A `--no-cache` run on zed printed "over its 2048 MiB budget — evicted 19 blob(s) of other roots". `--no-cache` turns off the working-tree parse cache, but a verb that materializes a commit tree still writes that tree's HEAD-side cache on purpose: qheadsnap and qsnap for `--edit-check`, `--quality-delta`, `--quality-delta=REV|A..B`, `--quality-baseline` and `--dmm`, and qms for `--merge-scout`. Each of those writes ran the cache directory's once-per-process hygiene sweep. That is the 30-day age pass plus the 2 GiB byte-budget pass, and it covers every root's blobs. So a gate or agent that asked for no cache could turn other projects' warm caches cold.

A `--no-cache` process now runs no directory-wide sweep. Each family it writes keeps its own keep-2 cap, which only touches this root's blobs. The next cached run sweeps the directory as before. On a seeded cache directory with four other-root blobs of 700 MiB each and one blob aged past 30 days, `--no-cache` with `--edit-check`, `--quality-delta`, `--merge-scout` and `--dmm` each used to remove 3 of those 5. They now leave all 5 with the same inode, size, mtime and bytes. A plain cached run and a cached `--edit-check` still remove the aged blob and 2 of the 4 budget blobs, and say so on stderr. Gate: `test/nocacheevictcheck.sh`.
