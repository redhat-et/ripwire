### Changed — the legend-seen hook is ON BY DEFAULT with a hook install, and it REWRITES your ripwire commands

`skills/install.sh --hook` (and `--codex --hook`, and `--opencode`, whose only hook this is) now registers `hooks/ripwire-legend-seen.sh` alongside the advisory entries. It was opt-in since it shipped; the default was turned over on a measurement: with the hook installed, a session's answers from call 2 carry **about 3,184 fewer bytes each — a ~19 % cut in total answer bytes** (call 2 on one tree: 16,218 → 13,234 B), because the legend is **22.8–25.0 % of a bare CLI answer** and the hook stops you being sent definitions you already hold. The flag still exists for a hook-only install: `--hook-legend-seen`.

- **This default changes what the agent types, not just what ripwire prints**, which is a bigger commitment than a format change, so it is visible rather than silent. The installer prints the entries it will add, the line **"behavior: REWRITES a ripwire Bash command, only by inserting `--legend-seen=<session file>` after the binary word"**, and what it keeps on disk — all before it writes anything. `--hook`'s own banner now says that it brings a rewriting hook and names the way out. Every reduced answer also says in place where definitions were left out (`[legend-seen: N held]`, with the `dictv=` that holds them all), so a rewritten call is legible in the answer too.
- **Two ways off.** `skills/install.sh --hook --no-hook-legend-seen` installs the advisory entries without it (`--opencode --no-hook-legend-seen` then has nothing to install and says so); `RIPWIRE_LEGEND_SEEN=0` turns an installed hook off at run time. Passing `--hook-legend-seen` and `--no-hook-legend-seen` together is refused rather than resolved silently.
- **Unchanged: the hook, and the bare install.** Only the default moved. The hook still rewrites nothing but the binary word's tail, never returns a permission decision, never names the flag to a binary too old to take it, and forgets the file on resume, clear and compaction. A plain `skills/install.sh` still touches no settings file at all, and `--hook-subagent-primer` alone still installs only its own hook — the default rides on a `--hook` install, not on every run.
- **Still deterministic.** `--legend-seen=FILE` is read, never written, by the binary (`"rb"`, and deliberately not through the parser's own reader, so the file is not a dependency of the warm snapshot): an answer stays a pure function of argv, the tree and FILE's bytes. The hook lives outside the binary and changes its **inputs**; it does not give the binary a session. The 2026-11-18 refusal of an in-binary session default (output depending on earlier runs) is untouched by this.
- Gates: `test/legendseenhookcheck.sh` (i) and `test/legendseenportcheck.sh` (B) now pin the default in both directions — registered by a hook install, absent under `--no-hook-legend-seen` while the advisory entries stay — each arm red on the pre-default tree.
