### Changed — a receiver whose class another file states now binds to that class

A member call whose receiver is another call — C++ `ctx->getProcessList().insert(…)` or `Context::instance().get()`, Python `pilot.get_app().post_message(…)`, TypeScript `app.getRouter().match(…)` — now binds to the one class the inner call's declared return type names, when the inner call itself has one proven target. A Python local initialised from such a call (`a = pilot.get_app()`) takes the same class; a C++ local does not yet (C++ call-result typing stays off). In Python, a `@property` whose return is annotated and a field assigned from an annotated parameter (`def __init__(self, app: App): self._app = app`) are stated field types too. Stated types only, and only when exactly one in-tree class has the name: an unannotated parameter, an inner call bound by name alone, or a class name two classes share keeps today's `via="name"` hedge or decline. C++ and Python results are read by that one-class rule.

`kParserVer` 299 → 301 (file tag 302): C++ functions record their declared result on every build, Python functions record theirs, and a member call on a call result records its receiver shape. `kCacheVersion` 48 → 49 (a binding kind is appended), so an older cache is re-parsed once.
