### Changed — a cold run writes its cache in 4 MiB pieces, so large repos peak 5-7 % lower cold

A run that parses from source saves its cache before it builds the graph. The whole cache file was first assembled in memory, in one buffer that grew by copying itself, and on envoy and vscode that save set the run's peak: 209 MB above the parse on envoy, 422 MB on vscode. The file is now written through a 4 MiB window as it is serialized, so the save adds a few MB, and the peak is the graph build again. Peak memory footprint, cold, median of five interleaved runs on macOS: `--deps` envoy 487 to 461 MB and vscode 976 to 909, the default map envoy 497 to 470 and vscode 963 to 905. Cockroach's cold peak was already the graph build and does not move, warm runs do not save and do not move, and the rich verbs' cold peak (`--for`, the MCP server's first index) is now set by the rich model build, which is unchanged. Speed is unchanged (instructions within 1.1 % either way). The cache file is byte-for-byte the same apart from its write-time stamp, and answers do not change: `--deps` and the map are identical on the three repos, cold and warm, and so is every one of the 321 stored `--for` and map calls.
