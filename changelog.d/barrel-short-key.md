### Fixed — `--for` follows TS/JS namespace re-exports, checks every segment of a written qualifier, and gives an unresolved name a fallback ladder

- `--for` `<reexports>`: a TS/JS namespace hop is now a row. `import * as X from './m'` followed by a local `export { X }` (or `export { X as Y }`), and `export * as X from './m'`, publish the whole module under `X`; the row says `ns="X"`. Behaviour change: `export * as ns from` used to be no row at all (the old legend said so); it is now an `ns=` row, and `test/reexportcheck.sh` arm T2 was rewritten with it.
- `--for` `<reexports>` on a qualified subject (`Q.leaf`, `Q::leaf`): every segment of `Q` must be accounted for. Full proofs: the file stem or a dot-suffix of it (`Completions` for `ts.Completions.ts`), the path's own tail (`utils.legacy` for `src/utils/legacy.ts`), a package index file's directories (`utils` for `src/utils/index.ts`), the whole owner path, or a namespace hop that publishes the definition under `Q`. Two weaker proofs only hedge: a directory elsewhere on the path (`src/utils/legacy/old.ts` for `utils`, `q_by="dir"`) and a consumer's own `import * as Q from …` (`q_by="alias"`); a hedged definition is listed only when nothing proves `Q` fully. The definition carries `q=` and its proving chain prints first. When one definition proves `Q` fully, a same-named one that cannot is no longer listed, so such a task may print fewer definitions than before. When none does and a cue word asks where the name comes from (`where is utils.formatDate defined`), every chain still prints, marked `q_unmatched="1"`. A subject that is one code-shaped name (the whole task) now prints its chain without a cue word; a bare `Q.leaf` prints only chains with some proof. A `this.X` / `self.X` subject is a member access and gets no block. A namespace re-export cycle (`a.ts: export * as B from './b'`, `b.ts: export * as A from './a'`) now ends without reaching the spelling cap.
- `--for`: a name-exact route that resolved no definition (`reason="no_candidates"`, empty `<sigs>`) now prints a `<shortkey>` block with a fallback ladder, each rung named: `leaf` (a dotted key's last segment, filtered by the same qualifier proof; exactly one fully proven definition is `exact="1"` and its body is printed, several are hedged with `cands=`, hedged-only proofs say `q_by="alias"` or `q_by="dir"` and are never exact, none is `q_unmatched="1"`; C++ stores only the innermost owner, so a namespace segment stays unproven), `substring` (definition names containing the key, never exact) and `literal` (declaration-shaped source lines the index does not store as definitions: `using X =`, `typedef … X;`, `type X`, `#define X`, `… as X` on an import line, `const`/`let`/`var`/`static X`, `X =` at column 0; comment lines are never rows). Every block carries `next=`; rows are capped at 6 per rung with `total=`, a printed body is cut past 8192 bytes with `truncated="1"`, and `floor="1"` marks a literal scan that could not read every file. The rungs can all be empty (`total="0"`). Only XML answers on a single root carry the block: `--json`, `--format=candidates` and multi-root answers print neither the block nor a marker; under `--token-budget` a held marker prints instead. A `this.X` / `self.X` subject gets no ladder. `RIPWIRE_NO_SHORT_KEY=1` turns it off.
- Measured on the practice questions this targets: `--for=Completions.getCompletionsAtPosition` on TypeScript went from a 1.3 KB answer with no definition to the namespace hop and the definition's body; `--for=ColumnPtr` (ClickHouse) and `--for=ExprType` (RisingWave) now name the `using` / `use … as` lines that declare them. Gate: `test/barrelshortkeycheck.sh`.
