### Added — `--for` lists a function's prototypes when a signature change is in question

A `--for` task about one C, C++ or Go function's signature (signature, prototype, new argument), or the function's bare name, now carries `<decl_rows>`: its definition and every non-test declaration the index holds, including the header prototypes `--defs` folds into the definition's row. Present only when such a declaration exists. `functions="N"` says when the rows are N separate functions (a static elsewhere, an overload, another scope): a change reaches its own definition row and the `decl_only` rows right after it. `untied="1"` marks a prototype the index could not tie to a definition (a name match: still a declaration of that name at its line, possibly of another function of the same name). A name that is both a macro and a function stays silent. A macro name is never the subject (`PyAPI_FUNC(int) f(int)` names `f`); the bare form resolves the whole spelling only (`api.c` is silent). A token budget holds the block as `held="budget"`; its `next=` is the same `--for` call without the budget, which prints the rows (`--defs` folds a tied prototype into its definition). Capped at 8 rows (`shown=`, `capped="1"`, `next=--defs=`, which lists definitions with their prototypes folded). Not listed: call sites, the implementations of an interface contract (`--lego`), and prototypes hidden behind a macro (`__P((..))`, `DECLARE_FN(name, t)`).
