### Fixed — a Rust call with a turbofish on a path function or a method is a call

`W::assoc::<u8>(2)`, `crate::util::deep::<T>(x)` and `w.method::<u32>(4)` were not references at all: tree-sitter-rust wraps the callee in a `generic_function` node, and the Rust tags query read that wrapper only around a bare name (`free::<u32>(1)`). `--callers`, `--uses`, `--impact` and every verb built on the call graph missed these sites. On zed, `--callers=register_setting` listed 0 files and now lists 8, every file `rg` finds calling it (7, plus the definition's own file). `--callers=open_panel` went from 0 files to 9, `toggle_panel_focus` from 0 to 10 and `receive_notification` from 0 to 12, each also every `rg` caller file plus the definition's. The receiver's type and the path qualifier pick the definition exactly as they do for the same call written without the turbofish. A `macro_rules!` transcriber's `$w.m::<T>(..)` and `a::f::<T>(..)` are now calls of the macro too. A turbofish on a type segment (`Vec::<T>::new`) was already read and is unchanged. Gate: `test/rustturbofishcheck.sh`.

Versions: kParserVer 342 → 344 (rich 345), so a warm cache from before this change re-parses. kCacheVersion unchanged.
