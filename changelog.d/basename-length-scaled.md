### Changed — `--for` lifts every symbol of a file the question names by the same amount, whatever its length

A question word that names a file (`widget` for `widget.py`) adds that file's name to the ranking evidence of every symbol in the file. BM25 then divided that evidence by each symbol's own length, so a long function or class gained several times less than its five-line siblings and could sink behind them: in a test fixture a 300-line function the question is about fell from rank 1 to rank 41, behind all 40 short helpers of its file. The file-name evidence is now scaled by the symbol's length factor (never below the old amount), so after BM25's division a long symbol keeps what a mean-length one keeps; short symbols score exactly as before. `--for`, `--pack-task` and the MCP `for` verb share it; `--query` and `--recall` do not use the file-name field. `RIPWIRE_BASENAME_FLAT=1` restores the unscaled field and `RIPWIRE_BASENAME_W=0` still turns it off.

Measured offline, page 1 of the default `--for` answer, against 0.7.0-dev main `6c018f611`, on three in-sample sets that ripwire was tuned on (not a held-out result): 163 everyday questions, 56 large-repository questions and 89 GA1 development questions. Complete answers 210 → 212 of 308 (everyday 121 → 122, GA1 67 → 68, large 22 → 22), no question lost a credited item on page 1 or on the unpaged answer, page-1 bytes −741 in total. One of the two gains (the everyday one) is credited through a test-file name in a file list rather than the function itself, so treat it as fragile. Gate: `test/forbasenamelengthcheck.sh` (new).
