### Fixed — a `--for` answer's `<syms>` block keeps a header declaration apart from an unrelated same-name definition (thanks CodeRabbit, #555)

The `<syms>` block folds a bodyless C/C++ header declaration into a same-(scope, name) definition in another shown file, so the definition's row stands for both. Until now it did that with no check that the two were one function, so an unrelated namesake in another shown file could replace the header's row. A declaration now folds only when the definition's file answers its header: the definition is in a file that `#include`s the header, directly or through other headers (an umbrella header such as `tmux.h`, or a quote include written from an include root, `#include "include/api.h"` in `src/`), or the two share a path stem (`src/foo.h` and `src/foo.c`, `.cc`, `.cpp`, `.cxx`, `.m`, `.mm`). Otherwise both rows print and the header keeps its row. An angle include, or an include no rule resolves, ties nothing, so such a pair prints two rows. Measured on the 36 C-family calls of the 321 in-sample `--for` calls: 24 printed rows came from a fold, and all 24 still fold (every definition file there includes its header); one call (mf1-tmux-04) changes after the prototype rule, `name_total=` 54 to 55 (a header declaration that had folded into a source-file prototype keeps its own row), with the five printed rows identical, and the other 35 are byte-identical. `test/forfilesymscheck.sh` arms k1-k7 cover C and C++: an unrelated definition, a direct include, an umbrella header, a shared stem, a root-relative include, a source file holding only the prototypes, and an uppercase `.C` stem. The case came from a CodeRabbit review on #555; the prototype and `.C` cases from the one on #566 (thanks CodeRabbit).
