### Added — C++ `using` aliases, namespace aliases and function-pointer typedefs are definitions, and `--defs` prints their target

- C++ `using X = Y;` (plain, templated `template<class T> using V = …;`, and class-scope `using value_type = …;`), `namespace L = lib;`, function-type and function-pointer typedefs (`typedef void (*Fn)(int);`, `typedef int Fn(int);`, `t="functype"`) and pointer typedefs (`typedef struct S *SP;`) are now definitions. `--defs=ColumnPtr` on a tree with `using ColumnPtr = COW<IColumn>::Ptr;` used to find nothing; it now lists the alias. A `using` written inside a function body or lambda stays a local name, and `using namespace ns;` / `using ns::name;` add no definition.
- `--defs` rows for a `using` or namespace alias carry `to=` (the written target, whitespace folded), `to_next=` (the defs call for the target: `--defs=Owner::leaf` when that spelling binds a definition, else the last name segment, which may list namesakes) and, when the file can no longer be read, `to_unread="1"`. A target longer than 160 bytes is cut with an ellipsis and marked `to_capped="1" to_bytes=N`. The JSON form carries the same keys. A `typedef` row keeps its old shape (no `to=`).
- Because aliases are now definitions, a name-exact `--for` on an alias lands on it (on ClickHouse, `--for=ColumnPtr` now routes name-exact and prints `IColumn_fwd.h`'s declaration), and C++ trees gain namesakes where an alias shares a name with another definition.
- A `--for` sentence around a name whose only definitions are `using` or namespace alias rows (``what does `using ColumnPtr = ...` expand to``) still gets the `<shortkey from="sentence">` ladder, so its literal rung prints the `using` lines; a name that also has another definition stays resolved. A literal row no longer names its own alias row as `in=`.
- TypeScript module-level `const` values are unchanged. Gate: `test/aliasdefcheck.sh`.
