### Added — `--for` prints the top-ranked doc sections for a prose question about the docs

A `--for` task written as prose (no backtick, `::`, `()`, snake_case, camelCase or dotted call) whose first ten file-tail rows hold two or more doc files (`.md`, `.markdown`, `.mdx`, `.rst`, `.txt`, `.html`, `.htm`) now ends with `<doc_body>`: the sections of the first three doc files the answer shows that rank highest for the task's words, chosen the way `--recall` chooses them. Each section row names its file, source lines, heading and rank in that file. The block has its own allowance of 7500 bytes of text, outside `est_tokens`, so the rest of the answer is unchanged; a cut says `capped="1"`, `dropped=` and `next=` the `--recall` call. A section is a lexical match, not a checked answer, and the block's legend says so. A token budget holds the block (the files named, `next=` the call without the budget). `--json` carries it as a `doc_body` key and MCP `for` carries the same element over its own rows. `RIPWIRE_NO_FOR_DOC_BODY=1` turns it off. Gate: `test/fordocbodycheck.sh`.
