### Added — `--callees` names the calls the resolver left unbound and undeclined (`<unres>`)

A call whose name is defined in the tree but that kept no edge and no decline record was silent on `--callees`: no row, no `<dc>`, only the corpus-wide `graph_unresolved=` gauge counted it. Two resolver outcomes had that shape: every in-tree definition of the name was filtered out (another language's only, a known-indirect call, a local or closure, a refused ES import), and a Rust call whose written qualifier ruled every in-tree definition out on a path not provably outside the tree (a `pub use` re-export the scope guard does not read). Measured on 61 callee cells over zed, nushell, cockroach, terraform, envoy, cpython, vscode and jq, these were cpython's `PyErr_Occurred` (its C definition is not extracted, so only a Python test definition is in reach) and zed's `language_model::read_credentials`. buildGraph now records each such call (`Graph::unresolvedSites`, kept in the warm snapshot, 8 B per call), and the callees answer names the called names once, first call first, on one `<unres n= calls= more=>` line after `<stdm>` (at most 8 names; `more=` counts the rest). It is not an edge: no `count=`, row or `hop_tested=` moves. `--json` and the MCP `find_symbol` twin carry `"unres"`; the columnar form carries neither, as with `<stdm>`. New gate `test/unrescalleescheck.sh`.

Versions: warmsnap `kVersion` 14 (the GRAPH section carries the records).
