### Fixed — Rust `crate::f()`, `self::f()` and `super::f()` calls bind their target

A Rust call written from a module keyword in one segment — `crate::rootfn()`, `self::sibling()`, `super::helper()`, `super::super::f()` — drew no call edge. `--uses` listed the site and `--callers` listed nothing. The qualifier kept for a path call is its last segment, so these calls had the qualifier `crate`, `self` or `super`. The Rust qualified-call scope guard keeps a candidate only when its scope or file module is the one the qualifier names, and no def's scope or module is spelled `crate`, `self` or `super`. Every such call was therefore dropped as qualified-external. `crate::a::f()` already bound, because its qualifier `a` names `src/a.rs`, which is why only the one-segment keyword spelling was affected.

The guard now reads a keyword path in full from its root. A candidate survives when it is a free item (a top-level item, or a member of the inline `mod` the path reaches) of exactly the module the path names, in the caller's own crate. A type's method is never a module item, so `crate::paint()` still ignores `Widget::paint`. The path is read against the module layout where the layout knows the crate (a `lib.rs` or `main.rs`). Where it does not, as in a `[lib] path = "src/x.rs"` crate, it is read against the Cargo.toml manifest's own crate root, the same table `use crate::…` imports already resolve through. Gate: `test/rustpathkwcheck.sh`.

The same holds for a call a `macro_rules!` transcriber spells: `crate::f($x)` and `$crate::f($x)` are now calls of that macro, as the bare `f($x)` already was. Measured on zed: one-segment `crate::f()` sites with an edge went from 3 to 204 of 295, `super::f()` from 1 to 95 of 100, with 296 sites leaving `qualified_external` and no existing edge changed.
