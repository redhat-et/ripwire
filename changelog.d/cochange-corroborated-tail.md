### Changed — a one-file co-change question fills its list with corroborated 2-commit partners (`floor_tail="corroborated"`)

With one seed file (`--cochange=FILE`, a one-file `--situ`, a one-seed `--pack-task` `<partners>`, and their MCP twins), the support floor of 3 shared commits often left nothing to show: across 200 sampled commits of kubernetes, 73 one-file questions got no partner. Dropping the floor to 2 found more of the files that really changed together, but it also listed noise. So the floor stays 3, and the list is now filled up to 10 with 2-commit partners that something else corroborates. A partner qualifies when it moved in at least half of the seed's commits, or when the code links the two files: an include or import edge either way, a call edge either way, a test-of pair, or the same directory of 20 indexed files or fewer. These rows always rank below every 3-commit partner and never displace one. Each row says why it is listed (`why=support|confidence|link`), and the answer carries `floor_tail="corroborated"`. A question with several seed files is unchanged.

Backtest (`bench/cochange` protocol, seed 1126, one file of a real commit as the only seed), Hit@10 at floor 3 → with the tail: ripwire 0.505 → 0.555, kubernetes 0.500 → 0.615, django 0.270 → 0.360, fastify 0.458 → 0.510. The share of listed partners that really changed in the commit went from 0.156 to 0.160, 0.240 to 0.231, 0.182 to 0.178 and 0.205 to 0.201. All three conditions of the rule recorded before the run hold. New gate `test/cochangetailcheck.sh`.
