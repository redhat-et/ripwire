### Fixed — `--edit-check` flags a required parameter added in C, C++, Rust and Go, and answers a C/C++ bare name whose header was not updated

After a required parameter was added to a C, Rust or Go function, `--edit-check` answered `incompatible="0"` beside callers that still pass the old count (verb-audit2: 0 of 5 non-TypeScript cells flagged it; TypeScript flagged 36/36). The arity test read ingest's call-comparable arity, which those languages never get, so every definition there accepted any call. A C++ definition that already carried a default or a parameter pack was the same wildcard. `src/editcheckarity.h` now gives every definition in the overload set an accepted RANGE, read off its signature for C, C++, Rust and Go: C `(void)`, a `...` tail and a prototype-less `()`; C++ defaults (on the definition and on a declaration of it) and packs; a Rust `self` receiver (a method call omits it, a path call `T::m( &x, … )` writes it); Go `a, b int` grouping, a `...T` tail and a method expression. A call is flagged only when no overload's range accepts it. A list the reader cannot hold to the indexed parameter count (a macro where the parameters belong, for one) is never guessed: the root says `arity_unknown="N"` and nothing is flagged against it.

`--edit-check=NAME` also refused as "2 distinct contracts" once a `.c`/`.cpp` definition gained a parameter its header declaration did not (5 of 7 bare cells exited 1; 2 of those 5, jq, are this shape, the vscode and zed ones are two real definitions and stay refused). A declaration that would declare the definition but for its parameter list (same name and scope, the definition's file includes it, same C++ scope chain and qualifiers) is now merged into it, and the answer names it: `decl_pair="FILE:LINE" decl_params="N"`, the header's old count — itself the finding, since a caller that sees only the header compiles against the old list.

`test/editcheckaritycheck.sh` holds both, per language: a required parameter added (the stale caller flagged, the base binary flagged none), a compatible add (a C++ default, a C/Go variadic tail, a Rust type change and an unchanged receiver method), the bare name (C/C++ `decl_pair=`; Rust/Go answer, and two real definitions in two files stay refused), an unread macro-built list, and C++ overloads (flagged only when no overload fits).
