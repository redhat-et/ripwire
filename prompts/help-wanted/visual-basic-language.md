# Visual Basic (VB.NET): first-class support

You are bringing **Visual Basic .NET** into ripwire as a first-class language. That means a
vendored tree-sitter grammar, symbol and call extraction, the disclosures that say what the grammar
cannot see, and a red-first gate. The extension is `.vb`.

This prompt is self-contained. `prompts/add-a-language.md` is the general form of the path and is
worth reading. Every step VB needs is repeated here, together with what was verified about the VB
grammar landscape on **2026-09-11**. Re-check anything dated before you rely on it.

**The short version:** a VB.NET tree-sitter grammar exists, but it is not usable as a dependency
today. It has no license file, no upstream maintenance since July 2025 and no test corpus, and it
lacks rules for constructs that nearly every real VB file uses. So the first deliverable is a
**grammar that clears the parse-rate bar**, either upstream or new. The ripwire integration comes
second. Both are real work, and other tools will inherit the first one.

Work in a git worktree, not the main checkout. Run gates in the foreground.

---

## 1. Why this matters

- **Large enterprise and legacy .NET codebases are written in VB.NET.** These include
  line-of-business WinForms applications, internal tools, and libraries nobody on the current team
  wrote. They are exactly the codebases a newcomer, human or agent, can least afford to read blind.
  Microsoft's strategy keeps VB supported with a stable design. It takes a consumption-only
  approach to new runtime features and keeps investing in interop with C#, "especially in core
  Visual Basic scenarios such as Windows Forms and libraries"
  ([Visual Basic language strategy](https://learn.microsoft.com/en-us/dotnet/visual-basic/getting-started/strategy)).
  A stable design is good news for a grammar author, because the target is not moving.
- **Real VB code exists at scale, in public.** The VB compiler in
  [dotnet/roslyn](https://github.com/dotnet/roslyn) is written in VB: 1,394 `.vb` files under
  `src/Compilers/VisualBasic`. The VB runtime library is a `.vbproj` in
  [dotnet/runtime](https://github.com/dotnet/runtime) (`src/libraries/Microsoft.VisualBasic.Core`).
  Several of GitHub's most-starred VB.NET repositories are actively maintained applications:
  [CompactGUI](https://github.com/IridiumIO/CompactGUI), [staxrip](https://github.com/staxrip/staxrip)
  and [DISMTools](https://github.com/CodingWonders/DISMTools).
- **It is on the SCIP list.** The [SCIP indexer table](https://github.com/sourcegraph/scip) lists
  `scip-dotnet` for C# and Visual Basic. VB support arrived in
  [scip-dotnet v0.2.0](https://github.com/sourcegraph/scip-dotnet/releases) (2023-06-05). The
  project's plan is to support every language on that table first-class, as well as we can
  ([#70](https://github.com/redhat-et/ripwire/issues/70)).
  - ripwire already indexes Java, TypeScript, JavaScript, Rust, C, C++, Ruby, Python, C#, Dart and
    PHP.
  - Kotlin is in review ([#126](https://github.com/redhat-et/ripwire/pull/126)), and Scala has its
    own kit.
  - **Visual Basic is the other gap.**
- **First-class means the whole tool**, not a navigation-only row. That covers bodies, complexity,
  clones, lint, `--match`, parse health and the call graph, all from the one offline binary without
  building the target project. SCIP stays what it is today: an optional precision overlay
  (`--scip`).
- **It is interesting.**
  - No production-quality VB.NET tree-sitter grammar exists, so grammar work here helps every
    tree-sitter tool, not only this one.
  - VB is **case-insensitive**, and no language ripwire indexes today folds case during name
    resolution. You would design the first one.
  - VB lives in mixed VB/C# solutions. That puts real pressure on the cross-language rule the Kotlin
    review just paid for (section 6).

## 2. The grammar: what exists (verified 2026-09-11)

### The only VB.NET candidate: `CodeAnt-AI/tree-sitter-vb-dotnet`

It was found by GitHub search and announced in
[tree-sitter discussion #4530](https://github.com/tree-sitter/tree-sitter/discussions/4530) on
2025-07-24. Each fact below can be checked with one command or one page.

| Question | Answer (at upstream `main`, commit `cfca210ce8fd`) |
| --- | --- |
| Activity | 13 commits between 2025-07-24 and 2025-07-28, all by one author. Last push 2025-07-28. |
| Open work | PRs #2, #3, #5 and #6 are open. Grammar-fix PR #8 was closed **unmerged** on 2026-08-14. |
| License | **No LICENSE file.** `package.json`, `Cargo.toml` and `tree-sitter.json` declare MIT. [Issue #7](https://github.com/CodeAnt-AI/tree-sitter-vb-dotnet/issues/7), "Unlicensed code", has been open with no comments since 2026-05-01. |
| ABI | `src/parser.c` was generated by tree-sitter 0.25.8 with `LANGUAGE_VERSION 15`. ripwire's vendored core (v0.26.9) accepts ABI 13 to 15, so it would load. |
| Scanner | None (`EXTERNAL_TOKEN_COUNT 0`), so none of the serialization hazards recorded in `third_party/patches/README.md` apply. |
| Entry symbol | `tree_sitter_vb_dotnet`. `parser.c` is 10.3 MB. |
| Test corpus | **None.** There is no `test/corpus/`, so `tree-sitter test` has nothing to run. `test/` holds two sample `.vb` files (511 B and 4.2 KB) and their printed trees. |
| Queries | No `queries/` directory, so there is no upstream `tags.scm` to adapt. |
| Self-declared status | The README lists LINQ/XML literals as planned, preprocessor directives as parsed only as trivia, and error recovery as basic. It targets VB 16.9. |

Reading `grammar.js` at that commit shows missing rules for constructs common in real VB. This is
a reading, not a measurement; STEP 0 measures.

- `class_block` expects `Inherits` and `Implements` on the **same line** as `Class Name`. The
  WinForms designer writes `Inherits System.Windows.Forms.Form` on the next line.
- Generic type arguments are `Of T` with **no parenthesised form**, so `As List(Of String)` has no
  rule.
- `method_declaration` has no `Handles` clause and no member-level `Implements` clause.
- Members cannot be nested types. `#Region` is accepted only where a statement is, not between
  members.
- There are no rules for:
  - `Operator` declarations, `Declare` statements, `Await` and `Yield`
  - the `RaiseEvent`, `AddHandler` and `RemoveHandler` *statements* (only the custom-event accessor
    blocks exist)
  - `Imports` aliases
  - XML literals
- Identifiers are an ASCII-only regex, and the grammar declares no `word` token.
- Implicit line continuation appears only after commas in list rules.

Downstream fixes exist, but **none is upstream**:

- [PR #8](https://github.com/CodeAnt-AI/tree-sitter-vb-dotnet/pull/8) was found while vendoring the
  grammar into another code-intelligence tool and parsing real WinForms sources. It fixes
  next-line `Inherits`/`Implements`, `Handles`, `AddHandler`/`RaiseEvent`, `As New`, member-level
  `#Region` and nested types.
- A [fork](https://github.com/Kellett/tree-sitter-vb-dotnet) (2026-08-25) carries a longer fix list,
  including parenthesised `(Of ...)`, import aliases, nullable types and a `word` token.
- [Another fork](https://github.com/jamie8johnson/tree-sitter-vb-dotnet) (2026-03-07) adds a LICENSE
  file.

None of them combines the grammar fixes with a license from the original author.

### Not candidates

Some grammars look related but target different languages:

- **VBA:** [tmepple](https://github.com/tmepple/tree-sitter-vba),
  [harumiWeb](https://github.com/harumiWeb/tree-sitter-vba),
  [arrmee-wt](https://github.com/arrmee-wt/tree-sitter-vba)
- **VB6:** [joannefan](https://github.com/joannefan/tree-sitter-vb6)

[Linguist](https://github.com/github-linguist/linguist/blob/main/lib/linguist/languages.yml) maps the
extensions like this:

| Language | Extensions |
| --- | --- |
| Visual Basic .NET | `.vb`, `.vbhtml` |
| VBA | `.bas`, `.cls`, `.frm`, `.vba` |
| VB6 | `.bas`, `.cls`, `.ctl`, `.Dsr`, `.frm` |

Never map the VBA or VB6 extensions to a VB.NET grammar.

### Verdict

**No usable VB.NET grammar exists today.** One exists, but ripwire cannot vendor it:

- No upstream commit has a license file, and `test/dependencypincheck.sh` requires
  `third_party/deps/<dep>/LICENSE`.
- Upstream is unmaintained, and there is no test corpus.
- The rule gaps above make a low parse rate likely.

So this kit is about **finishing or writing a grammar** first, then integrating it. There are two
routes, and your plan picks one with evidence.

- **Route A: revive upstream.**
  1. Ask on issue #7 for a LICENSE commit.
  2. If the author adds one, land the fixes upstream. PR #8 and the fork are starting points, and
     their authors' agreement matters too.
  3. Add a `test/corpus/` suite.
  4. Pin ripwire to the resulting upstream SHA.
- **Route B: a new grammar in its own public repository**, under MIT or Apache-2.0. Write it from
  the language specification ([dotnet/vblang](https://github.com/dotnet/vblang), `spec/`) and from
  the compiler's own MIT-licensed definition of VB syntax nodes in Roslyn
  ([`src/Compilers/VisualBasic/Portable/Syntax/Syntax.xml`](https://github.com/dotnet/roslyn/blob/main/src/Compilers/VisualBasic/Portable/Syntax/Syntax.xml)).
  Do **not** derive it from the unlicensed `grammar.js`.

Either way, the grammar lives **outside** this repository:

- ripwire pins a commit SHA and vendors the generated sources verbatim. It does not carry grammar
  forks.
- `third_party/patches/` exists for vendored code that is wrong for ripwire's use; every current
  patch is a sanitizer-safety fix. It is not for missing coverage.

## 3. STEP 0: the measurement that decides whether to integrate

Run this **before any ripwire code**, and be willing to stop here. Start with the grammar at
`cfca210ce8fd` as a baseline, then measure the grammar you intend to pin (your fork or your new

### Corpora

These were checked through the GitHub API on 2026-09-11. Record the commit you measure.

| Corpus | Why it is here | Size | License |
| --- | --- | --- | --- |
| [staxrip/staxrip](https://github.com/staxrip/staxrip) | A pure VB.NET WinForms application with no C#. | 145 `.vb` files (17 `*.Designer.vb`), 2 `.vbproj` | MIT |
| [dotnet/roslyn](https://github.com/dotnet/roslyn), `src/Compilers/VisualBasic` | The VB compiler, written in VB. Its tests embed VB source as XML literals. | 1,394 `.vb` files (919 under `Portable/`, 474 under `Test/`) | MIT |
| [IridiumIO/CompactGUI](https://github.com/IridiumIO/CompactGUI) | A mixed solution with 2 `.vbproj` and 2 `.csproj`. This is the section 6 corpus. | 57 `.vb` files and 21 `.cs` files | GPL-3.0 (measure it; never vendor it) |

Two optional additions:

- [CodingWonders/DISMTools](https://github.com/CodingWonders/DISMTools): 483 `.vb` files, 173 of them
  `*.Designer.vb`. Use it if generated designer code is where your numbers look suspicious.
- [dotnet/winforms](https://github.com/dotnet/winforms): 133 `.vb` files of Microsoft-authored VB
  beside C#.

### What to report

1. **The headline.** The fraction of `.vb` files whose tree contains no `ERROR` node and no
   `MISSING` node, per corpus. Report `*.Designer.vb` separately. Generated designer code and
   hand-written code fail differently, and one must not hide the other.
2. **The damage.** The share of bytes under top-most `ERROR` spans. A file with one error in its
   last method still yields most of its symbols. A file that fails at `Inherits` yields nothing.
3. **The work list.** The ten most frequent constructs at a file's first error, each with one
   verbatim source line. This list is the grammar plan.

### Two instruments, which must agree

1. **The tree-sitter CLI.** Use the version that generated `parser.c`, or newer:
   `tree-sitter parse -q -s -p <grammar-dir> <files...>`. Here `-s` shows parse statistics, `-q`
   suppresses the trees and `-p` names the grammar directory
   ([parse docs](https://tree-sitter.github.io/tree-sitter/cli/parse.html)).
2. **The number ripwire will actually ship.**
   - Today's binary lists every `.vb` file under `--skipped` as `why="unsupported-ext"`. The
     `--skipped` legend calls that the class of row that hides a whole language.
   - Make a throwaway worktree with the grammar wired locally (STEP 2's registration and a
     definitions-only query).
   - Run `./build/ripwire <corpus> --skipped --no-cache`. It emits
     `<h why="degraded-parse" err= err_ratio=/>` for every indexed file whose parse contains
     `ERROR` or `MISSING` nodes.
   - Count those rows against the number of `.vb` files.

If the two instruments disagree, find out why before you believe either.

**The bar** comes from `prompts/add-a-language.md`:

- A grammar that parses about 95% of real-world code is worth vendoring.
- One that parses 55% ships a map that loses half the language behind an honest header, and that
  is worse than no grammar at all.

**Write the numbers into the PR even if they are low.** A low number with its work list is a
finding, and an upstream grammar PR needs it anyway.

**Optional third instrument, strongly encouraged.**
[`scip-dotnet`](https://github.com/sourcegraph/scip-dotnet) (Apache-2.0) indexes VB, but only for
projects that build. Where they do, its index is an oracle:

- Its definition occurrences give symbol recall.
- ripwire's `--scip` overlay plus `--pin-census`, following the protocol in
  `bench/scip_pin_precision.py`, measures how often name-based VB edges pick the right target.

## 5. VB-specific design

Each subsection ends in decisions your plan must make, and each decision needs a gate arm.

### Case-insensitive identifiers

**What is true.**

- The VB compiler treats names that differ only in case as the same element, and name comparison
  does not depend on locale
  ([Declared Element Names](https://learn.microsoft.com/en-us/dotnet/visual-basic/programming-guide/language-features/declared-elements/declared-element-names)).
- The CLR binds **case-sensitively**, so a C# caller of a VB assembly must match the declared case
  (same page).
- The Common Language Specification requires identifiers to differ by more than case. It treats two
  identifiers as the same when their lowercase mappings are the same
  ([Language independence](https://learn.microsoft.com/en-us/dotnet/standard/language-independence)).

**What ripwire does today** (as of `766913d0`):

- Call resolution looks names up byte-exactly (`byName` in `src/graph.h`), and no language folds
  case there.
- Case-insensitive helpers exist for other jobs: `rw::ciEqualAscii` in `src/arch.h`, and the
  whole-name match `--for` uses in `src/lexical.h`.

**Decide:**

1. **Where the fold happens.** Fold at resolution, for VB references only. Never rewrite stored
   names. The map, `--callers` output and the identities `--edit-check` and `--quality-delta` use
   all keep the declared spelling.
2. **Exact match first.** An exact-case candidate wins, and folded candidates join only when the
   exact lookup finds none.
   - Several folded candidates is honest ambiguity (the CLS rule exists for exactly this), and goes
     through the existing ambiguity disclosure.
   - It must never become "first in crawl order". The memo trap in `prompts/add-a-language.md`
     shows how crawl order and filenames end up deciding the answer.
3. **What folds.** Use a fixed ASCII table, never anything locale-dependent: output must not change
   with the machine's locale. VB allows non-ASCII letters in names, but upstream's identifier regex
   does not, so those files read as degraded parses today. If your grammar accepts them, state the
   rule for non-ASCII letters and gate one arm.
4. **What is not part of the name.**
   - **Type characters.** `Name$` and `Name` are the same element: Microsoft's
     [Type Characters](https://learn.microsoft.com/en-us/dotnet/visual-basic/programming-guide/language-features/data-types/type-characters)
     page says the type character is not part of the element's name. Upstream's identifier token
     includes that character.
   - **Escaped names.** `[Error]` uses brackets to escape a keyword. Decide whether its key is
     `Error`, and gate it.
5. **Selectors.** Selectors are exact today. Should `--callers=getcustomer` find `GetCustomer` in a
   VB corpus? If you fold, fold for VB symbols only, and refuse on ambiguity rather than picking one.
6. **Contracts.** A case-only rename of a **public** VB member changes nothing for VB callers but
   breaks every C# caller. `--edit-check` must not call it "no change". Add one fixture arm.
7. **Determinism.** No hash-map iteration order may reach the output, folded candidate lists are
   ordered by node id, two runs are byte-identical, and warm equals cold.

### Declarations

- **`Namespace`.** Source shows only part of the full name.
  - Every namespace sits under the project's **root namespace**, which is set in the `.vbproj` and
    defaults to the project name. `Namespace Global.X` escapes it
    ([Namespaces](https://learn.microsoft.com/en-us/dotnet/visual-basic/programming-guide/program-structure/namespaces)).
  - Scope-qualified ids built from source alone are therefore partial. Disclose that; reading the
    `.vbproj` is a later round.
- **`Module`.** A module has one instance, its members are implicitly `Shared`, and every member's
  scope is promoted to the containing namespace
  ([Module Statement](https://learn.microsoft.com/en-us/dotnet/visual-basic/language-reference/statements/module-statement)).
  - Bare calls to module members are the common case, which suits name-based resolution.
  - When two modules define the same member, the caller must qualify it.
- **Kinds.** Map `Class`, `Structure`, `Interface`, `Enum`, `Delegate`, `Sub`/`Function`,
  `Sub New`, `Property` (with `Get`/`Set`), `Event` and `Operator` onto the kinds C# already emits
  (`symTag` in `src/model.h`) before you invent any new ones.
- **`Partial`.** A partial type is split across declarations and files, all in one assembly and
  namespace
  ([Partial](https://learn.microsoft.com/en-us/dotnet/visual-basic/language-reference/modifiers/partial)).
  - At most one declaration may omit the keyword.
  - The compiler merges parts whose fully qualified paths are identical.
  - WinForms puts one part in `Form1.vb` and one in `Form1.Designer.vb`.
  - Gate arm: a call from either part resolves, and `--lego` sees the base class that only the
    designer part declares.
- **Member-level `Implements`.** A clause like `Implements IWorker.Run` names the interface member
  explicitly, and Microsoft documents reimplementing a member under a different name
  ([Implements Clause](https://learn.microsoft.com/en-us/dotnet/visual-basic/language-reference/statements/implements-clause)).
  An implementors view that matches by name alone will miss these. Decide how to handle it, and add
  an arm.
- **`Declare`.** This is a native entry point with no body. Index it as a declaration and disclose
  it.

### `Handles`, `WithEvents`, `AddHandler`, `AddressOf`

**What it means.**

- `Sub Button1_Click(...) Handles Button1.Click` wires a procedure to an event raised by a
  `WithEvents` variable or by the base class.
- `AddHandler` does the same at run time
  ([Handles Clause](https://learn.microsoft.com/en-us/dotnet/visual-basic/language-reference/statements/handles-clause)).
- No source line calls the handler.

**Why it matters.** Left alone, `--callers` reports zero callers for every WinForms handler. And
`--dead-code`, which lists functions with no caller in the indexed tree, reports every handler as
dead.

**Recommendation for the first round:**

- Record `Handles Button1.Click` as **references** to the field `Button1` and the event `Click`,
  not as a call edge.
- Decide how `--dead-code` treats a procedure that carries `Handles`. Today its only exemptions are
  self-registering test macros and the `register_macros` config key.
- Disclose it.

**Later rounds:**

- An event-to-handler **edge** is framework dispatch. If it is ever added, it belongs in a separate
  round, it needs its own provenance, and its legend change goes through `docs/METHODOLOGY.md`
  section 9.
- `AddressOf Foo` uses a function as a value. The nearest precedent is the function-pointer binding
  tables (`FnPtrBindTables` in `src/graph.h`); read them, but don't reuse them blindly.

### Line continuations

- An explicit continuation is a space, an underscore and the end of the line. Since VB 16.0 a
  comment may follow the underscore
  ([Break and Combine Statements](https://learn.microsoft.com/en-us/dotnet/visual-basic/programming-guide/program-structure/how-to-break-and-combine-statements-in-code)).
- Statements can share one line when separated by `:` (same page).
- Many tokens also continue a line implicitly, but upstream accepts implicit continuation only after
  commas.

Gate arms:

- A definition with a continued parameter list keeps the right span.
- A call split across lines is attributed to the right caller.

### Late binding

- With `Option Strict Off`, calls on an `Object` bind at run time. The initial VB default in Visual
  Studio is `Off`
  ([Option Strict](https://learn.microsoft.com/en-us/dotnet/visual-basic/language-reference/statements/option-strict-statement)).
- Name-based edges there are guesses, the same class of problem as dynamic dispatch elsewhere.
- Disclose it; don't pretend to resolve types.

### XML literals

**The feature.** XML can be written directly in VB code
([XML Literals Overview](https://learn.microsoft.com/en-us/dotnet/visual-basic/programming-guide/language-features/xml/xml-literals-overview)):

- It compiles to LINQ to XML objects.
- It embeds expressions with `<%= ... %>`.
- It spans lines without continuation characters.

**The cost.**

- Upstream lists XML literals as planned.
- Lexing them with embedded expressions is context-sensitive, so it probably needs an external
  scanner.
- A scanner brings the serialization and bounds duties recorded in `third_party/patches/README.md`,
  which is the defect class `test/vendorpatchcheck.sh` audits.

**First-round option.** Files with XML literals stay indexed and read as degraded parses. They are
**counted** in the PR's numbers, never dropped. Roslyn's VB tests are the adversarial corpus for
this.

### Preprocessor

- `#If`, `#Else` and `#Region` are trivia upstream, accepted only where a statement is.
- ripwire's dead-region logic (`src/preprocdead.h`) is C-family.
- Index both branches of an `#If` and disclose it.

### Runtime functions

- Calls such as `MsgBox(...)` and `InputBox(...)` have no definition in the corpus; Microsoft's own
  Module example uses both.
- A repository method with the same name will attract those calls.
- In the first round, disclose the floor. Don't ship a guessed list of runtime names.

## 6. Cross-language with C# in one solution

### What is true

- A project compiles to one assembly in one language.
- VB and C# projects mix in one solution through project references, and each produces its own
  assembly (see the discussion in [dotnet/roslyn#21024](https://github.com/dotnet/roslyn/issues/21024)).
- Any .NET component can be used from any .NET language
  ([Language independence](https://learn.microsoft.com/en-us/dotnet/standard/language-independence)).

So a VB call can legitimately reach a C# definition in the same solution, and a C# call can reach a
VB one. dotnet/roslyn is such a solution (GitHub counts about 77 MB of VB and 255 MB of C#), and so
is CompactGUI.

### The risk: the Kotlin lesson

While reviewing Kotlin ([#126](https://github.com/redhat-et/ripwire/pull/126)), maintainers measured
what an unguarded bridge did.

**What happened:**

1. Kotlin↔Java bare-name admission in `langCompatible` (`src/graph.h`) let test-only Kotlin
   `body()` functions join Java calls' candidate sets.
2. Java's `Response.body` stopped being a unique global name.
3. The resolver's locality ladder (same file, then same directory, then a unique global, else no
   edge) dropped the calls.
4. On square/retrofit, `Response.body` went from **279 callers to 5**. Files Java never references
   deleted 253 Java (caller, callee) pairs, and every header gauge stayed where it was.

**The fix was an own-language-first rule.** A Java or Kotlin reference admits the other language's
candidates only when its own language defines no candidate of that name.

- With the rule, retrofit is back to 279 callers.
- Its stated cost is one Kotlin pair across retrofit, ktor and nowinandroid: a same-directory
  cross-language target can lose to same-named own-language definitions elsewhere.

**Current status.** As of 2026-09-11:

- #126 is still open, and that filter (`keepOwnJvmLanguageCandidates` in the review fix) is not on
  `main`.
- [#136](https://github.com/redhat-et/ripwire/pull/136) has merged (d752d953), so those silent drops
  now show as `declined=`.

Search for the filter before you design. If #126 has landed, generalise its filter instead of writing
a second one.

**Case folding makes the .NET version worse.** A folded VB lookup for `tostring` meets every C#
`ToString`, `Equals` and `Dispose` in the solution.

### Recommendation

- **Round 1 is VB-only.**
  - `langCompatible` admits VB↔VB and nothing else.
  - Prove it on a mixed corpus: the set of C# (caller, callee) pairs is identical with and without
    the `.vb` files present.
- **Round 2 is a separate PR, after an owner go-ahead.** It adds a .NET bridge with
  own-language-first from the first commit.
  - **Case is one-directional.** C# to VB matches exact case, because the CLR binds
    case-sensitively. VB to C# folds, with ambiguity disclosed.
  - **Retrofit-shaped conservation arm.** A name defined once in C#, plus same-named VB definitions
    in two other directories, must leave the C# callers unchanged.
  - **The mirror image.** A name defined once in VB, plus same-named C# definitions elsewhere, must
    leave the VB callers unchanged.

## 8. Known traps

**Version bumps and their mirrors.**

- `kParserVer` and `kIngestParserVerMirror` move together, in one commit.
- Parallel lanes claim the same next number. #126 hit that twice while rebasing, and re-bumped to
  the next free value each time rather than keeping either side's number.
- Choose your number at merge time, not at branch time.

**The qschemetrip re-pin.**

- A change in extraction source text moves `test/qschemetrip.hash`.
- Re-pin with `UPDATE_GOLDEN=1 test/qschemetripcheck.sh`, and add the justification to that script's
  RE-PIN LOG.
- Bump `kQSnapCacheScheme` only if a snapshot layout actually changed.

**Generated artifacts are regenerated, never hand-merged.** Regenerate them on the **merged** tree;
a capture recorded on your branch describes a tree that no longer exists after the merge. They are:

| Artifact | How to regenerate or check it |
| --- | --- |
| `docs/COMMANDS.md` | `python3 docs/docs_commands_build.py --bin build/ripwire` |
| the showcase capture | `test/showcase_capture.py`, checked by `test/showcasecapturecheck.sh` |
| `docs/LIMITS.md` | `python3 docs/limits_build.py --check` |
| the gate count | `python3 docs/gatecount_build.py` |
| `test/printf_parity.manifest` | re-pin after the `--help` text moves |

**A clean merge with the wrong population.** Git merges text, not meaning. Kotlin appends to
`enum class Lang` too, and a textually clean merge can still leave:

- `kLangCount` naming the wrong last enumerator
- `kLangTable`'s array size one short
- two lanes sharing the same `kParserVer`

The Dart landing found seven per-language arrays sized off `Lang::Elixir + 1`. Appending Dart
silently dropped it from the `--skipped` language census: 2,959 files and 39,570 symbols went
missing. After every merge, run:

1. a clean rebuild
2. the doctor grammar count
3. `test/langcensuscheck.sh`
4. `test/qextractionkeycheck.sh`
5. a `--skipped` run that shows your `<lang>` row

**A binary that cannot exist.** Touching `src/model.h` while a build runs, or building across a
branch switch, produces objects that disagree on `sizeof(Symbol)`. Rebuild with
`cmake --build build --clean-first -j` whenever sources may have moved. `CLAUDE.md` describes the
symptoms, including ASan reports of bugs that do not exist.

**Two case-insensitive layers.** VB folds case, and so does the default macOS filesystem: a lookup
for `Customer.vb` can succeed on `customer.vb`. Put a case-colliding decoy in the fixture and assert
that the right file wins.

**Documentation is gated.**

- Every long flag named in prose must exist in the binary's full help (`test/deckcheck.sh`).
- Committed files must carry no absolute home-directory paths (`test/ripwirepubliccheck.sh`).
  Captures made with an absolute root carry one.

**A gate that has never failed** is no evidence that it can detect anything. Show it red.
